# 服务缺口与不可中断任务中断机制诊断（M6-P1-F2）

> 唯一 run：`runs/m6_service_gap_diagnosis_v1/`。train-only；origin **48 / 4848 / 10176**，
> 固定提案 compute ∈ {1.0, 0.5, 0.25}（储能 0），corrector **on / off** 对照，同种子。
> **off 仅为机制对照，不是正式基线**。只做诊断，未修改任何调度 / 环境 / 门槛语义。

## 3. on/off 与不同 compute 的首次改变点（答第 3 问）

- **on↔off 的首次改变点就在第一处不可中断中断本身**：off 轨迹**全程没有**任何
  不可中断中断，按时率 1.0、期末剩余 0；on 轨迹从该步起出现中断并逐步累积。
- **compute 1.0 与 0.5 在两种模式下都给出完全相同的结果**——说明在有无 corrector
  两种情形下，该固定提案的强度差异都被抹平（corrector 完全改写动作，见 `delta=1.0`）。
- compute 0.25 略有不同（首次中断更晚、中断数更少），但同样**不达标**。
- **两种模式均未出现任何物理违规**，故物理约束**不是**本次观察到的缺口的成因。

## 4. 三类候选原因的证据归属（答第 4 问）

| 候选原因 | 证据 | 结论 |
|---|---|---|
| **容量 / 接入限制** | 首次中断当步接入**仍有 5.35 kW 余量**（未触顶），且 off 模式在同一动作下服务完美、违规为 0；但「分组计划能力」当步**已用尽**（未用能力 ≈ 2e-11） | **接入限制：不支持**。**分组能力用尽**是事实，但它是 corrector 给出的 `planned_capacity_vec` 被用满，而**同一动作在 off 下并不用满** ⇒ 属下面第二项的后果，**非独立成因** |
| **修正器投影** | 首次中断当步 `raw→exec` 计算维修正达 **1.0（最大）**、`correction_reason=deadline_shortfall`、当步实际待执行 3 个任务、**仅 1 个被执行**；off 模式零中断零缺口 | **支持**（本卡最强证据） |
| **任务分配顺序** | 被中断任务**已启动**、当步到期、剩余仅 3.518 却未获分配 ⇒ 分配顺序未能保护临近到期的不可中断任务 | **支持（但为修正器投影的下游表现）**：分配结果由 corrector 投影后的动作决定 |

**明确未定位**：本卡**未**判定 corrector 内部是哪一阶段（Stage A/B、目标权重或
投影后取整）导致 6→1 的任务收缩；也**未**判定修正器「应有的」行为。两者都需要在
实施卡中带消融实验单独定位。
