# M6 正式评估协议（提前准备稿）

> 状态：**协议准备，不是正式评估结果**。M6-P0 先固定比较口径；业务服务阈值的数值已由 **M6-P1-F5（2026-09-28）冻结为 `m6-service-standard-v1`**（见 §2.1）。checkpoint 契约稳定后实施 M6-P1 评估器，并只用受控短跑 checkpoint 验证。正式训练产物经审核后才运行 validation 和最终 test。

## 1. 主问题与比较范围

主问题：**在达到同一业务服务标准、遵守同一物理约束时，联合滚动修正能否降低购电成本和购电归属碳排？** 两项分别报告金额（SGD）与排放（kgCO₂e），不预先合成加权总分。电池退化费另列，不混入“购电费”。

同一评估日期、任务流、初始队列/SOC、容量、外生驱动、因果预测、归一化参考值和环境种子用于所有可比较方法。没有合格 checkpoint、方法尚未实现或运行失败时，保留失败记录；不得伪造中性动作或静默改用旧模型。

五类方法是：规则、独立滚动优化、**新 21 维契约下重新训练**的惩罚 PPO、安全 PPO＋单步修正、安全 PPO＋联合滚动修正。改变训练中的修正方式须重新训练对应 PPO 变体，不能只在评估时替换修正器却称作该方法的正式结果。旧 23 维 PPO checkpoint 仅可单列历史参考，必须由新主链版本/维度门禁拒绝。

## 2. 业务服务资格

一个 episode 的业务服务门槛按下列**已冻结**标准预注册（冻结记录见 §2.1）：

1. 截止时点落在本 episode 内的任务，按任务数与原始工作量分别计算按时完成率；两者均须 **≥95%**。分母包含已到期但失败或仍积压的任务，不能因状态为 `failed` 而消失。截止时点在 episode 外的任务单列“未到期积压”，不计作已逾期。
2. 期末剩余工作量（含初始积压与本段到达任务的未完成部分）≤**初始积压工作量＋本段已到达任务原始工作量**的 **1%**；同时单列剩余工作绝对值。零分母时标为不可判定，不自动合格。
3. 不可中断任务的中断次数为 **0**。任何接入上限、SOC 边界、充放电互斥或能量守恒违规，以及缺失必要证据的 run，均不能进入“同等服务”成本/碳比较。

95%／95%／1%／0 是研究目标的**提案值，不是从已观察结果倒推的阈值**：它们先由 M6-P1（协议 §2，未冻结）提出，再由 M6-P1-F1 在**修复前**的 train-only 环境上做可行性审计，最后由 M6-P1-F4 在 F3-R2 修复后的环境上复审并**通过**，据此冻结。正式训练前可用 train-only 数据做可行性审计；若目标在既定物理约束下不可达，应报告不可达并进行方向决策，不得看 validation/test 后下调目标，也不得放松物理或任务约束。评估器**不得**默认 `service_qualified=true`。

对不达标结果仍完整报告任务、经济、碳和失败指标；仅“同等服务下成本/碳更低”的**配对比较**要求该配对中的方法都达到预注册服务门槛。每张比较表同时给出合格配对数、全部预定配对数和不合格/失败原因，避免只展示容易的日期。

## 3. 单 episode 指标与来源

| 类别 | 必报指标及口径 | 当前环境来源/后续核对 |
|---|---|---|
| 业务服务 | 按时完成、逾期完成、逾期积压、未到期积压：任务数与原始工作量均列；期末剩余工作量；不可中断任务中断次数 | 任务逐项状态/期限及终点 `task_classification`、`terminal_leftover_work`、`total_non_interruptible_interruption_count`；分类须覆盖已到达的 failed 任务 |
| 经济 | 购电费 SGD、电池退化费 SGD 分列；不将罚项加进 SGD | `total_cost`、`total_bess_degradation_cost`；`total_objective_cost` 含非货币期末罚项，只能标为混合目标诊断量 |
| 碳与购电 | 购电归属总排放 kgCO₂e、每单位已完成工作排放、购电量 kWh | `total_carbon_emission`、`total_completed_work`、`total_grid_energy_kWh`；零完成量时单位排放为不可判定，不填 0 |
| 物理 | 接入、SOC、充放互斥、能量守恒违规次数与最大幅度；电网峰值 kW | 每步物理 info 与现有守恒口径；`episode_grid_peak_power_kW`；数值容差沿用对应物理测试，不另设宽松阈值 |
| 风光 | PV、风电各自可用/使用/弃电量 kWh，以及各自 `used / available` 利用率 | 环境各自 `total_*_available/used/curtail_kWh`；可用量为 0 时利用率记不可判定；`renewable_share` 是可再生供能占 IDC 用能比例，须另名报告 |
| 修正器 | raw→exec 计算维和储能维修正幅度、业务缺口、求解耗时中位数/P95、超时/安全回退次数 | transition/info 的 `raw_action`、`exec_action` 与 `correction_*`；无修正器的方法标不适用，不填“0 次修正”冒充测量 |
| 可靠性 | 成功、失败、未评估 run 的数量及原因；失败率 | run manifest 与完整预定实验矩阵；失败 run 不从分母删除 |

（历史背景，已由 M6-P1 修正）`evaluation/adapter.py` 原为骨架：`service_qualified` 由调用者传入且默认 `true`，`renewable_utilization` 的分母是 IDC 用能，实为可再生**占比**，而 `EvaluationRecord` 未覆盖上表。M6-P1 已修正这些口径并删除默认达标路径；现行实现见 §2.1 的接线要求，不得把占位字段当正式评估。

## 4. 配对、种子与区间

保留每个 episode 的原始记录，再按**连续日期块**和训练 seed 分层汇总。首轮至少 3 个独立训练 seed；更换任务 seed 不算增加独立测试日期。规则/优化基线与 PPO 在相同日期及场景 seed 上配对。主表分别给出购电费与购电归属碳排的配对差、区间、逐 seed 值、服务合格率和失败率；同时列出全部日期的无条件描述统计。

区间估计以预先固定的连续日期块为重采样单位，训练 seed 作为独立层；明确记录块长度、重采样次数及 95% 区间方法。样本不足时展示原始分布和“不足以作稳定区间判断”，不只给均值。采用区间和多次运行而非单一点估计，符合 [Agarwal 等对强化学习评估不确定性的建议](https://arxiv.org/abs/2108.13264)。

## 5. 实施与数据使用顺序

1. **完成（M6-P0 + M6-P1-F5）**：审核并固定本协议结构，确认业务服务阈值的方向；阈值已冻结为 `m6-service-standard-v1`（§2.1）。M9.1a 资源短跑可独立继续。不得使用 validation/test 做阈值选择。
2. **checkpoint 契约稳定后（M6-P1）**：实现统一评估记录、五方法适配边界和服务资格判定；对 21 维/观测维度/schema/版本/来源/配置做加载检查。尚未实现的方法明确输出“未评估”状态。用受控短跑 checkpoint、train-only 场景及失败夹具验证评估器、计量、泄漏门禁与可复现性；该 checkpoint 不用于性能结论。
3. **正式训练产物审核通过后**：在冻结协议下运行 validation，只在每个预定方法内部选择 checkpoint/预登记候选；随后锁定选择规则和报告模板。最终 test 对全部预定方法只运行一次，覆盖预定的至少 30 个不同测试日，不按结果改阈值、日期或方法。
4. **M9.2/M9.3**：冻结完整实验矩阵并执行五方法公平对照；任何缺方法、失败或不合格都保留在报告中。旧 23 维结果只能作为独立历史参考。

## 6. 冻结的实验矩阵（M9.2）

共享场景、训练与评估日期、种子、五方法席位与统计规则已冻结为
**`configs/experiments/m9_experiment_matrix_v4.json`**（M6-P2b；`status = frozen_matrix`），
从 v3 继承实验设计，仅更新库存训练语义与配置绑定。旧 v1/v2/v3 保留。
`scenario.inventory_release.load_matrix()` 校验设计逐字段相同与所有来源的 live hash。

要点：

- **时间切分保留 v5 原样**：train 2024-01-01→2024-08-01、validation →2024-10-01、
  test →2025-01-01。日对齐 origin 天数 **212 / 61 / 92**（比例 58.08% / 16.71% / 25.21%）。
  实施计划写的 60/20/20 **并未满足**，该差异已在矩阵与 M9.2 卡中**如实登记**，
  **不重切数据**、不声称已满足。
- **评估日期**：validation 全部 **61** 个 + test 全部 **92** 个不重叠日 episode，
  各 split 内 origin 从 `candidate_origins.start` 起每 48 步一个；清单**只**由 split manifest
  的时间与 origin 元数据生成（未读真值、未跑评估）。
- **训练日期**：train 内 212 个日对齐 origin 的固定池；512 批 × 4 episode，
  `origin(b, s) = pool[(4b + s) mod 212]`，**三个训练 seed 共用同一预登记顺序**，
  环境与策略 RNG 仍按冻结配置分别派生。受控短跑的 24-origin 顺序**不是**本表顺序。
- **五方法席位**：规则 / 独立滚动优化 / 新 21 维惩罚 PPO / 安全 PPO＋单步修正 /
  安全 PPO＋联合滚动修正——当前**全部**为 `planned/not_runnable`（未实现或无正式配置），
  席位与缺项清单保留，**不造参数、checkpoint 或假运行**。
- **配对与统计**：配对单位 = (split, episode_start, scenario_seed)，主场景种子为 0；
  training_seed 0/1/2 只用于结果分层，基线每场景运行一次并在各层引用，不增加独立样本数。
  主比较是**同等服务与库存条件下**
  购电费 SGD 与购电归属碳排 kgCO₂e **分列**；按连续 **7 日块**、以训练 seed 分层的 95% 区间，
  末尾不足 7 日的块保留；失败与不合格者完整报告但不进入配对差。

**矩阵冻结 ≠ 正式训练放行。** `formal_env_ready=true` 不代表可训练或可评估；
v4 继承矩阵中 `formal_training_ready=false`；正式训练由独立的训练发布 v2、
实际代码/资产验签，以及三种子各 8 批的 train-only 短跑闸门合取放行。
旧 checkpoint 无法恢复新版训练或进入新版正式评估，只能用于显式历史诊断。
validation/test 仍须等待新训练产物复审；训练成本是否漂亮不作为 readiness 门槛。

M6-P2b 共同终点目标为既定 50% SOC，合格区间仍为 45%–55%。双方完整 episode、
冻结服务标准与物理约束通过，且终点电量差 ≤1e-6 kWh，才生成公平成本/碳配对差。
滚动规划覆盖真实 episode 的全部剩余步数；因果预测与明确声明的窗口外假设不变。
规划中不可达、求解失败/超时、实际终点与规划终点的偏差分别报告。
实际库存不合格本身不构成预测误差的归因证据。终点恢复诊断量不冒充已发生的购电。
联合滚动安全 PPO 修复通过也只占一个席位；仍缺规则、独立滚动、惩罚 PPO、
单步安全 PPO 四个正式席位，不能称五方法比较已就绪。
