## 1. 目标

删除 `_base_shortage_possible()` 的静态启发式（`access + pv + wind < base`），改为**与主 LP 同物理约束**的「基础负载专用可行性诊断」，避免误分类。

## 2. 已发现的问题（改造前）

静态比较 `pf.base_idc_power[k] > access_limit_kw + pv[k] + wind[k]` **忽略储能**：
只要电池能在时域内补足缺口，基础负载其实是可服务的，但该启发式会误报 `base_shortage`。

## 3. 边界（允许修改的文件）

## 4. 禁止项

- 不改 contracts、动作空间、env、corrector、PPO、MIP 互斥逻辑；

- 不改 `marl/`、`grid_model/`、`legacy/`。

## 5. 诊断模型

与主 LP 相同的物理约束，但**不含任务相关变量**：

- H 步；`P_idc[k]` 固定为 `planning_forecast.base_idc_power[k]`；
- 相同的 `P_grid`（`[0, access_limit]`）、`pv_used`（`[0, pv]`）、`wind_used`（`[0, wind]`）、弃电定义、`charge`/`discharge`（功率上限）、SOC 动态与上下界、效率、无反送电与能量平衡；
- **不含** `A[i,g,k]`、business slack、deadline slack。

诊断 = 该 base-only 模型是否可行；不可行时再用非负「未服务基础功率」松弛量最小化，量化 `base_shortfall_kwh`。

**注**：主 LP 与 base-only 模型的可行域在能量侧等价（主 LP 可取 `A=0` 使 `P_idc = base`），
故主 LP 不可行 ⟺ base-only 不可行；`solver_failure` 分支保留给真正的求解器/数值失败。

## 6. 分类规则

仅当 base-only 诊断**不可行**时，主 LP 失败才分类为 `base_shortage`；否则分类 `solver_failure`。

## 7. 新增结果字段

`base_diagnostic_status`、`base_diagnostic_solve_time_s`、`base_shortfall_kwh`（不可行时量化；可行时为 0.0）。

失败语义不变：`allocation = 0`、`business_shortfall_work = 全部当前剩余工作`，**不虚构可行任务分配**。
