## 5. 第 0 步映射（精确写明）

**compute**（`group_work_capacity[g] == 0` 时 `u_g = 0`，不得除零）：

```
u_g = sum_i A[i,g,0] / group_work_capacity[g]
```

**storage**（正值=放电、负值=充电，范围 [-1, 1]，与环境符号一致）：

```
exec_storage = discharge[0] / discharge_max − charge[0] / charge_max
```

## 6. 投影目标（无量纲、可审计）

第 0 步 **L1 最小偏移**（不得混入任意货币权重）：

```
offset = (1/N) * Σ_g |u_g − raw_compute_g| + |exec_storage − raw_storage|
```

## 7. 两阶段确定性求解（仅 `backend="mip"`）

- **阶段 A**：在全部物理/业务硬约束与显式 slack 约束下，最小化上述 raw-action 偏移；相位内不混入经济目标。
- **阶段 B**：固定 `偏移 ≤ 阶段 A 最优值 + 容差`，再以现有规划经济/服务目标（电费 + 退化 + 业务/期限 slack，单位 SGD）作**确定性 tie-break**。
- 两阶段的**状态、耗时、目标值**均须在 Corrector 输出中可审计。

## 8. 失败语义

- 仅 MIP 第 0 步映射为 exec action；
- `deadline_shortfall` 可作为**已知业务风险**记录（≠ 物理失败），其第 0 步物理可行候选**可执行**；
- `timeout` / `infeasible` / `solver_failure` / `base_shortage` **必须零动作回退**，不得执行候选解；
- **无效 proposal**（维度/范围）安全零动作回退并记录明确原因；**合法 proposal 不得静默 clip 后冒充「未修正」**。

## 9. 接线要求

- `planning/corrector.py` **必须直接调用新 H 步 MIP 投影入口**，**不得**再导入或调用 `planning.solver.solve`；
- `FailureClass` 需保真表达：`timeout`、`base_shortage`、`solver_failure`、无效 proposal、`deadline_shortfall`、成功；
- `CorrectorWrapper`：
  - `raw_action` **逐元素原样**写入 info；
  - `exec_action` = 正确器第 0 步 MIP 投影输出；
  - reward、next observation、env info 均由 `exec_action` 产生；
  - 追加 planner backend、两阶段求解状态、投影偏移、业务缺口等审计字段；
  - 环境执行后，接入上限 / SOC 边界 / 能量平衡仍由 **M3 物理链**成立；
  - **不修改 raw log-prob 或任何 PPO 记录**。
