## 8. 人工复审结论（2026-09-29）

**部分通过。** v2 矩阵的切分/origin/服务标准/预算数值、库存记录字段与六条件门禁的
**代码逻辑**均可保留；导出接线跑通。以下四项须返修：

1. **矩阵文字与字段不一致**：v2 中规则法与独立滚动优化的 `blocking_reasons` 仍写着
   「尚无该方法的正式训练配置（冻结配置 v1 只覆盖 PPO + corrector 主链）」与
   「正式训练 run（512 批 × 3 seed）」等 PPO 训练口径，与其 `trains_ppo=false` /
   `explicitly_not_required` 自相矛盾。
2. **源 checkpoint 来源被导出时的 live 账本替换**：导出入口直接用**当前 live** 资产 hash
   组装来源账本并写入 run，**未**核对源训练恢复 checkpoint **自带**的 `frozen_config` /
   `source_ledger` / `code_revision` / 所选 origin 的 `origin_provenance`
   ⇒ 等于「用当前资产 hash 包装旧权重」，来源不可追溯。
3. **缺少源权重 vs 导出权重在完整 episode 上的等价证明**：现有 A/B 两条 run **都从导出件
   加载**，只能证明「导出件可复现」，**不能**称为「源 vs 导出」的对照。
4. **配对键未接入公平收益出口**：`assess_fair_pairing()` 未携带
   `(split, episode_start, scenario_seed)`，也没有产出
   `fair_purchase_cost_delta_sgd` / `fair_carbon_delta_kg_co2e` 的报告出口
   ⇒ 只是一个未被接入的 helper。

**勘误（须在 R1 卡、handoff 与新报告中更正）**：本次真实轨迹为**初始 50 kWh、终点约
90 kWh**，即**多存入约 40 kWh**；因此**不能**据此宣称「用掉电池换来购电费优势」。
保留「终点 SOC 0.9 超出目标容差 0.05 ⇒ 不可作公平配对」这一**实测事实**。
