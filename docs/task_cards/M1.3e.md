## 3. contract-v8 数据模型

`contracts/models.py` 新增 frozen、`extra=forbid` 的结构化模型：

1. **`ArtifactDigest`**：`role`、`logical_path`、`sha256`
2. **`ForecastSeriesProvenance`**：`series_name`、`source_kind`、`method`、
   `generated_at`、`information_cutoff_exclusive`、`target_start`、`target_end_exclusive`、
   `lookback_start`、`lookback_end_exclusive`、`model_name`、`model_version`、
   `code_revision`、`seed`（允许 `None`）、`sources: list[ArtifactDigest]`
3. **`ScenarioForecastProvenance`**：**七个固定字段**（不用自由 dict）——
   `price_forecast`、`load_forecast`、`pv_forecast`、`wind_forecast`、
   `temperature_forecast`、`carbon_forecast`、`arrival_forecast`
4. **`ScenarioBundle`**：`schema_version=contract-v8`；用明确 `mode`
   （`formal` / `synthetic` / `oracle_debug`）取代含糊的 `synthetic: bool`；
   新增 `generated_at`；新增结构化 `ScenarioForecastProvenance`；
   **移除**无 schema 的 `source_hashes`；`content_hash()` 必须覆盖**全部** provenance。

`source_kind` 至少区分：`external_forecast`、`seasonal_naive`、`persistence`、
`modeled_scenario`、`synthetic`、`oracle_debug`，**另加 `unavailable`**
（validator 明确要求 `mode=formal` 拒绝 unavailable 来源，故该取值必须存在）。

**不得**用自由 dict 同时承载上述语义；**不得**以默认值让缺 provenance 的旧构造通过。

## 4. contract-v8 验证规则

`contracts/validators.py` 必须验证：

- 所有时间戳均为**带时区的规范 ISO-8601**；
- `generated_at <= target_start`；`information_cutoff_exclusive <= target_start`；
  `lookback_end_exclusive <= information_cutoff_exclusive`；
  `target_start < target_end_exclusive`；
- provenance 的 `series_name` 与所在 `ScenarioBundle` 字段**一致**；
- 七个 forecast 字段与七项 provenance **一一对应，不缺不多**；
- `sources[*].sha256` 为 64 位小写十六进制；`code_revision` 为 40 位小写 Git SHA；
- `mode=formal` 时**拒绝** `synthetic`、`oracle_debug` 与 `unavailable` 来源；
- `mode=synthetic` 时必须明确 synthetic provenance；
- `mode=oracle_debug` 时必须明确 oracle_debug provenance；
- **独立 purpose gate**：`training`/`evaluation` 必须拒绝 synthetic 与 oracle_debug，
  只有 `debug` 才接受；
- 缺 `generated_at`、origin、model/version、可见窗口或来源 hash 时 **fail closed**；
- **不允许 `bool` 冒充 `int`/seed**；不泄漏 `KeyError`/`TypeError`/`AttributeError`。

## 6. 五类因果 forecast provider（`scenario/forecast.py`）

对五个 canonical truth driver 生成预测，**冻结**方法为
**trailing seasonal-naive，周期固定 48 个 half-hour steps**：

- 全局 origin = i：历史模板**只允许**读 `[i-48, i)`；
- forecast 第 k 项取该模板的 `k mod 48` 项；
- **绝不读取 i 或 i 之后的 truth**；
- `generated_at = information_cutoff_exclusive = lookback_end_exclusive = origin`；
- `target = [origin, origin+C)`；`C` 必须通过 **M1.3d `validate_forecast_origin`**；
- **train 内 `i < 48` 时 fail closed**，不回填、不跨年环绕；
- validation/test 起点允许使用**其之前已发生**的 canonical 历史，
  但**不得**用 validation/test 数据拟合、调参或重算 policy；
- `period=48` 是**冻结的物理日周期**，不从 validation/test 选择；
- 将来若需统计拟合参数，**只能来自 train**；本卡不得暗中增加拟合。

provider 返回**结构化、可 content-hash 的「available exogenous forecast artifact」**，
**不得**伪装成完整 `ScenarioBundle`。artifact 含：`split`、split-local origin、
global origin、`forecast_cutoff`、`generated_at`、target timestamps、上述五个 forecast
数组、每序列结构化 provenance、canonical/split/policy manifest hash、`contract-v8`。

### 13.4 provenance 模型、校验与 purpose gate

- **构造时 fail closed**：`ForecastSeriesProvenance` 与 `ScenarioBundle` 各自带
  `model_validator(mode="after")`。校验实现位于 `contracts.models`
  （`validators` 依赖 `models`，反向导入会成环），`contracts.validators`
  以同名语义入口 `validate_series_provenance` / `validate_scenario_provenance` 委托。
- **时间戳**：必须带时区且为**规范** ISO-8601（naive、`Z` 结尾等非规范形式拒绝）。
- **时间顺序**：`generated_at <= target_start`；
  `information_cutoff_exclusive <= target_start`；
  `lookback_end_exclusive <= information_cutoff_exclusive`；
  `lookback_start <= lookback_end_exclusive`；`target_start < target_end_exclusive`。
- **一一对应**：`ScenarioForecastProvenance` 刻意**不**继承 `ContractBase`
  （否则 `model_fields` 会混入 `schema_version`，「七个字段与七项 provenance
  一一对应」就无法机器判定）；每项 `series_name` 必须等于其所在字段名。
- **格式**：`code_revision` 40 位小写 Git SHA；`sources[*].sha256` 64 位小写十六进制；
  `sources` 不得为空。
- **bool 不得冒充 int**：pydantic 宽松模式会把 `seed=True` 变成 `1`、`"0"` 变成 `0`，
  因此 `seed` 走 `field_validator(mode="before")` 显式拒绝。
- **mode ↔ 来源自洽**（`MODE_ALLOWED_SOURCE_KINDS`）：
  `formal` 只接受 external/seasonal_naive/persistence/modeled_scenario；
  `synthetic` 拒绝 external_forecast 与 oracle_debug；
  `oracle_debug` 只接受 oracle_debug/synthetic。
- **purpose gate**（`validate_forecast_purpose`）：`training`/`evaluation` 只接受
  `mode="formal"`，其余（含 synthetic、oracle_debug，以及**不是** `ScenarioBundle`
  的 forecast artifact）一律拒绝；只有 `debug` 接受。**本卡只建立 gate**，
  正式训练接线属 **M1.3g**。

### 13.5 因果 forecast 与**人为裁定**的历史窗口勘误

冻结口径：`FORECAST_PERIOD_STEPS = 48`、`method = trailing_seasonal_naive`、
`target = [origin, origin+C)`、`C` 必经 M1.3d `validate_forecast_origin`；
`generated_at = information_cutoff_exclusive = lookback_end_exclusive = origin`；

（模板按**时间正序**，即 `forecast[k] = y(origin+k-48)`）；train 内 `origin < 48`
fail closed；无随机数。

> `test_history_window_changes_the_forecast` 原先只改 `origin-1`（第 199 行）
> 却要求 `cutoff=4` 下的 forecast 变化。按 §6 的冻结规则，第 k 项消费的行是
> `origin-48+k`；`origin-1` 落在模板下标 **47**，只有 `C > 47` 才会被消费 ——
> **卡片文字与测试互相矛盾**。已上报人工，裁定为**取卡片字面规则**
> （`forecast[k] = template[k mod 48]`），并把该测试的触发位置改为
> **整个历史窗口** `range(origin-PERIOD_STEPS, origin)`。
> **断言强度不变**：仍是「历史窗口的任何变化都必须体现在 forecast 上」，
> 仍为 `assert after.series[driver] != baseline.series[driver]`；没有删除、没有反转、
> 没有放宽。修正的是**触发位置**，不是判据。

**另一处由 leakage 回归暴露并修正的语义**：`content_hash()` 只覆盖**预测内容本身**
（contract_version / split / origin / global_origin / forecast_cutoff / frequency /
method / period_steps / generated_at / target_timestamps / series）。上游制品的
sha256 随上游字节变化而预测未必变化，把它们算进 content hash 会让「同一份预测」
在上游重物化后得到不同身份；上游 digest 仍完整保留在
`to_dict()["provenance"][*]["sources"]` 供审计。这正是
`test_origin_and_future_truth_do_not_change_the_forecast` 与
`test_validation_future_mutation_does_not_change_the_current_forecast` 明确要求的语义。

**上游校验范围**：provider 只对**它真正读到的字节**负责 —— split manifest 的
`canonical_parquet_sha256`、canonical manifest 的 `output_parquet_sha256` 与 parquet
实测 sha256 三者必须相等，外加 schema/行数/时区/频率与整条 canonical 时间轴校验；
**不**校验 canonical manifest 文件自身的 hash（那是 M1.3d `load_truth_split` 读取链的职责）。

### 15.6 严格冻结 artifact 与双摘要

`contracts.AvailableExogenousForecast`（`ContractBase` 子类，frozen + `extra=forbid`）：

### 15.7 leakage：两类 mutation 的结果

因果性**下沉到纯函数** `scenario/forecast.py::seasonal_naive_forecast()`：

```text
future-truth mutation keeps forecast: True      # [origin, end) 变化 → 预测不变
history-window mutation changes forecast: True  # [origin-48, origin) 变化 → 预测必变
forecast[0] == y(origin-48): True               # 卡片字面规则，模板按时间正序
```

provider 层另用**两条各自完整自洽的冻结链**（各自重算 hash 与 train-only 统计）
做对照，这不是「同步改几个 hash 绕过校验」：

```text
future truth 变化 → series 与 prediction_hash 不变；content_hash 与
                    canonical_parquet_sha256 变化（两个摘要语义因此可区分）
history window 变化 → series 与 prediction_hash 必须变化
被改写的冻结资产（parquet 字节） → provider fail closed
```

并补一条边界回归：只改模板下标 `>= C` 的行（`origin-1`，C=4）不改变预测，
但同一行在 `C=48` 时**确实**参与计算、必须改变预测——把「C 覆盖窗口末端」这个
错误前提固定成显式断言。
