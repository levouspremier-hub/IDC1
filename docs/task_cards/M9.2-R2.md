## 1. 四项修正

1. **v3 矩阵文字与字段一致**：规则法与独立滚动优化的 `blocking_reasons` 只列**其自身**
   尚缺的方法配置、实现与可追溯运行证据，**不再**写 PPO 训练配置 / 512 批训练 / PPO
   checkpoint；三个 PPO 席位维持各自训练与 checkpoint 要求。v1/v2 标为**历史版本**，
   原日期清单、origin 摘要、服务标准与预算**逐项不变**。
2. **源 checkpoint 来源不可被 live 账本替换**：导出前读取并**逐项核对**源 checkpoint 的
   `frozen_config` / `source_ledger` / `code_revision` / 所选 origin 的 `origin_provenance`
   与当前冻结配置、live 资产及该 origin 的**正式注入**；**只在一致时导出**，
   并在 run 中**同时**记录「源 checkpoint 自带值」与「live 重算值」。不一致即失败。
3. **源权重 vs 导出权重的完整 episode 等价证明**：用源 policy 与导出后正式加载的 policy，
   在**同一 train origin、`scenario_seed=0`、同一 corrector**下各跑完整 48 步，
   比较**完整 `EvaluationRecord` 与库存记录**；动作或必要指标不一致 ⇒ **不得**
   写 `status=success`。源 checkpoint 只读、**不**做参数更新。
   R1 的两条「都从导出件加载」的 run 保留为**历史**，但**不**得称作「源 vs 导出」对照。
4. **配对键接入公平收益出口**：公平配对输入显式携带
   `(split, episode_start, scenario_seed)`；键不同即**拒绝**配对。结果同时保留双方原始
   购电费、碳排、服务与库存记录；**只有**同键且服务、物理、初末库存条件全部通过，
   才填 `fair_purchase_cost_delta_sgd` / `fair_carbon_delta_kg_co2e`；
   否则两项为 **`null`** 并写原因。
