## 1. 缺陷（M5.4d 遗留，已实测复现）

M5.4d 的探针**记录了它没有执行的参数**。根因：`main` 把 `--steps` 写进 config，
但 `run_in_subprocess(mode)` 只把 `mode` 传给子进程，子进程里的
`run_once(mode)` 于是使用**默认** `steps=STEPS=8`。

### 1.1 `--steps` 与真实执行不一致

```
=== 1. --steps 1：config 说 1，实际 metrics/provenance 是几？ ===
    exit = 0
    config['steps']           = 1
    provenance[0]['steps']    = 8
    metrics['steps'][0]       = 8
    -> 不一致: True
```

**产物自相矛盾**：config 声称 1 步，metrics/provenance 记录 8 步。
探针的整个价值在于「可复核」，而它连自己跑了多少步都不一致。

### 1.2 `--steps <= 0` 未被拒绝，反而写出「成功」产物

```
=== 3. --steps <= 0 是否明确拒绝 ===
    --steps 0: exit=0 写了产物=True
    --steps -3: exit=0 写了产物=True
```

因为 `--steps` 根本没传到子进程，`--steps 0` 实际仍跑 8 步并**成功**；
而 config 会写下 `steps: 0` —— 即**一份声称跑 0 步的成功 run**。
这是比 §1.1 更严重的假记录。

### 1.3 `manifest.command` 缺参数，不可重放

```
=== 2. manifest.command 是否完整 ===
    command = python scripts/probe_corrector_repro.py --modes off --runs 1 --run-id s1
      --steps            在账本中: False
      --base-dir         在账本中: False
      --emit-provenance  在账本中: False
```

`--steps` 与 `--base-dir` 缺失 ⇒ 照此命令重放会得到**不同步数、不同输出目录**的 run，
与 M5.4c 建立的「命令账本必须完整」标准相矛盾。

## 3. 禁止项

1. **不得**升级 contract 版本。
2. **不得**用「config 写默认值」掩盖未传参。
3. **不得**在 `--steps <= 0` 时写出任何**成功**产物。
4. 不得改动 digest 的语义字段集合（属 M5.4f 的判定范围）。

## 4. 实现要求

1. `run_in_subprocess(mode, steps)` 必须把**实际** steps 传入子进程 argv；
2. `run_once(mode, *, steps)` 接收并校验 steps（必填关键字参数，无静默默认；
   `steps >= 1` 且为整数）；
3. `config` / `metrics` / `provenance` / `report` 记录**同一个**实际步数（单一来源）；
4. `manifest.command` 用 `shlex.join` 完整记录全部**有效**参数：
   `--modes` / `--runs` / `--steps` / `--base-dir` / `--run-id`，
   以及 `--emit-provenance`（仅当启用时）；
5. `--steps <= 0` 明确失败（`parser.error`，退出码非 0）且**不写任何产物**；
6. 测试用 `--steps ∈ {1, 3, 8}` **参数化**验证，不得只测默认值。

### 9.5 额外回归（参数保真不止 steps）

- **modes / runs 同样要真实**：`test_modes_and_runs_match_the_actual_metrics_rows`
  参数化 `modes ∈ {(off), (on), (off,on)}` × `runs ∈ {1,2}`，断言
  `len(metrics) == runs × len(modes)`、每个模式的 digest 数与 `report` 一致。
- **结构上不可能再有静默默认**：`test_probe_has_no_silent_default_for_steps_anywhere`
  用 AST 断言 `run_once` / `run_in_subprocess` 的 `steps` **没有默认值**。
- **写的就是跑的**：`test_recorded_parameters_are_the_ones_actually_executed`
  在 `--steps ∈ {1,3,8}` 下断言来自**实际采集**的 metrics/provenance 步数等于题设值。
