## 1. 目标

M5.2a 重建了带终端掩码的三套 target API，但 `safe_rl_v2/train.py` 仍在调用**已被移除**
的无掩码签名，当前 HEAD 上为红：

```
TypeError: compute_three_value_targets() missing 2 required keyword-only arguments:
           'terminated' and 'truncated'
```

本卡把该调用点接到 M5.2a 的唯一 API，并让三套 target 的**每一个输入**都来自 v6 buffer
的具名字段。**不新增 RL 数学**：不实现 PPO ratio/clip、不引入熵项、不改乘子语义。

## 3. 禁止项

1. **不实现** PPO ratio/clip、熵项或新的拉格朗日乘子语义。
2. **不得**对 `exec_action` 计算 log-prob；actor likelihood 仍只对 `raw_action` 重算。
3. **不得**保留旧的无终端掩码 GAE 调用路径。
4. **不得**混列三个 critic target、共享同一 cost target，或以电费（SGD）替代约束量。
5. **不得**以 dry-run 更新或损失数值宣称训练有效、收敛或性能改善。
6. **不得**回读 env 内部数组或未来真值来构造 target。

## 4. 实现要求

1. `dry_run_update` 必须调用 M5.2a 的 `compute_three_value_targets(..., terminated=, truncated=)`，
   且 `terminated` / `truncated` 由 buffer 的 `Transition` 字段**逐条**构造。
2. reward / business / carbon 三套 critic target 的输入**全部**来自 v6 buffer：
   `observation`（算 critic 估计）、`next_observation`（唯一 bootstrap 来源）、
   `terminated`、`truncated`、以及对应具名 signal
   （`reward` / `business_cost`（违规计数）/ `carbon_cost`（kgCO2e））。
3. bootstrap **只**读取 buffer **最后一条** `next_observation` 的 critic value；
   终止步不得使用它（掩码由 `terminated` 决定，不由调用方自行判断）。
4. critic loss 逐头对应各自 target：三个独立的 MSE，分别上报，不得混列。
5. actor likelihood 仍 `evaluate_raw_actions(buffer.observation, buffer.raw_action)`；
   本卡不引入 ratio/clip。
6. 返回指标必须标注单位与 bootstrap 语义，并带显式的 `claims` 块声明未训练。

### 4.1 新增返回字段

| 字段 | 含义 |
|---|---|
| `critic_targets` | 三头的 target 数组（逐头，单位见 `units`） |
| `critic_loss_by_head` | `{"reward":…, "business":…, "carbon":…}` 三个独立 MSE |
| `gae` | `{"gamma":…, "lam":…}` |
| `targets_source` | 固定字符串，标注调用的是 M5.2a 的唯一 API |
| `bootstrap` | `{"terminal": bool, "source": "buffer_last_next_observation", "used": bool}` |
| `units` | 各 signal 与累计量的单位（含「违规任务·步」约定） |
| `claims` | `trained` / `performance_evaluated` / `convergence_claimed` 全为 `False` |

## 5. 业务违规量单位（沿用 M5.2a §5）

`business_cost` = 环境的 `sla_violation_count` = **每步活跃逾期 SLA 违规计数**，
**不是唯一违约任务数**；rollout 内累计单位为「违规任务·步」。
电费（SGD）与碳排放（kgCO2e）是另外两套独立量纲，**不进入**任何 target。
**M5.3** 的预算必须按同一单位设定。

### 10.4 三种 bootstrap 行为的实测

| 情形 | 构造方式 | `bootstrap.terminal` | `bootstrap.used` | 断言 |

`bootstrap.source` 恒为 `"buffer_last_next_observation"`。

### 10.5 独立性、泄漏与端到端重算证据

- **三头独立**：把 carbon target 整体 +100 后，carbon critic loss 变化，
  reward / business critic loss **逐值不变**（`pytest.approx` 相等）。
- **电费隔离**：spy 断言传给 target API 的三个 signal 都不等于
  `electricity_cost_sgd` 序列；`units` 中三类量纲互不相同。
- **泄漏回归**（`@pytest.mark.leakage`）：`forecast_cutoff=2` 下改写
  `price_t[20]` / `pv_t[20]` / `carbon_factor_t[20]`，三套 target 与首条 raw 动作、
  critic loss **逐元素不变**。已反向确认**有齿**：改写 cutoff 之内的 `price_t[1]`
  会改变 reward target。
- **端到端独立重算**：用更新**前**的策略快照，仅依据 buffer 具名字段与 M5.2a 数学
  独立重算三套 target，与 train 上报的 `critic_targets` 在 corrector 开/关两路
  逐元素一致，并校验 `target = advantage + value`。

### 10.7 风险与阻塞

1. **本卡仍不是 PPO**：无 ratio、无 clip、无熵项；`Lagrangian` 仍是 M5.4 占位实现，
   **列为 M5.3 待重建**。dry-run 只证明「真实采集 → 三套 target → 一次更新」闭环可执行。
2. actor 项仍是 `-(adv_reward * log_probs).mean()`（仅用 reward 优势），
   乘子尚未进入损失——这是 M5.3 的内容，本卡未改。
3. `critic_targets` 以 numpy 数组随返回值一并给出，便于测试与审阅；
   它是**诊断量**，不是持久化产物（buffer schema 未变，仍为 `contract-v6`）。
4. `gamma=0.99` / `lam=0.95` 为模块常量，与 M5.2a 默认值一致；调参属后续卡。
