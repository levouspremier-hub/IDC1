## 3. canonical reader 契约

```python
load_singapore_2024_half_hour(raw_dir, source_manifest_path) -> pandas.DataFrame
```

返回表必须：**恰好 17,568 行**；按时间**严格递增**；**无重复、无缺失**；

## 4. 小时天气 → 半小时的**冻结映射规则**

采用 **“latest source timestamp not later than target timestamp”**：

- 目标 `h:00` 使用天气 `h:00`（`weather_age_minutes = 0`）；
- 目标 `h:30` 仍使用天气 `h:00`（`weather_age_minutes = 30`）；
- 逐行必须满足 `weather_source_timestamp <= timestamp`；
- **禁止**用下一小时天气填充当前半小时；**禁止**线性插值；
  **禁止** centered resampling；**禁止** backfill。

该规则必须写入 **canonical manifest 与文档**，不能只藏在实现里。
报告中不得简称“普通 forward fill”而省略可见性边界。

### 11.1 审核未通过的五个问题（改前实测）

#### 问题 1：最终 HEAD 幂等失败

```text
$ uv run python scripts/materialize_singapore_2024.py --frozen-at-utc "2026-09-15T00:00:00+00:00"
exit=1
ValueError: …singapore_2024_half_hour.json 已存在且内容不同（差异字段：['code_revision']）；不得静默覆盖
manifest code_revision = d9df46ae85061bef6aef768a9bba67faaaa4f2e5
当前 HEAD               = 60508ee1da3a293dd78069c5fcadd7ad466b603
```

根因：`code_revision = git_revision()` 记录的是**生成时刻的分支 HEAD**，
于是**任何后续提交（哪怕只改文档）都会让冻结数据失效**。

#### 问题 2：docs-only 提交不得使冻结数据失效

与问题 1 同源：`ac8ba3a…485491d` 之后的 `248d0dc`/`60508ee` 只改文档，
却已经使同一物化命令 exit 1。

#### 问题 3：manifest 不一致时**先改写 parquet**（失败原子性）

改前实现顺序是「先 `to_parquet(正式路径)`，再 `verify_existing(manifest)`」，
于是**失败的运行也会改写正式 parquet**。实测（exit 1 的那次）：

```text
before parquet mtime_ns: 1789471433230524092
after  parquet mtime_ns: 1789471451095282513   -> CHANGED   （sha 未变，但 mtime 已变）
manifest mtime_ns      : 未变
```

#### 问题 4：完全相同时不得重写

同源：`to_parquet` 无条件重写正式 parquet，故幂等成功时 parquet 的 `mtime_ns` 也会变。

#### 问题 5：路径不可移植

入库 manifest 记录了**机器绝对路径**：

```text
"path": "/Users/levous/Desktop/IDC/data/raw/singapore_2024/emc_usep_2024.zip"
contains '/Users/levous': True
```

不同 checkout 根路径下会产生不同的（且含用户名的）provenance。

### 11.2 返修要求

1. **revision 语义**：`code_revision` 改为 `materializer_revision` ——
   **当前 HEAD 可达历史中，最后修改数据生成实现文件的提交**
   （`scenario/singapore_2024.py`、`scripts/materialize_singapore_2024.py`），
   经 Git 解析得出，**不得**由调用者传入未经验证的 revision。
2. **失败原子性**：候选 parquet 先写**临时文件**（同一文件系统），
   算出候选 hash 与候选 manifest 后**先比较**；
   不一致 → 删临时文件、正式 parquet/manifest **完全不动**；
   一致且正式 parquet 已匹配 → 删临时文件、**不重写**；
   正式 parquet 缺失/损坏 → 仅当候选 hash 与冻结 manifest 相符时**原子恢复**；
   首次冻结 → 原子替换安装。异常退出不得留下半成品。
3. **路径可移植**：入库 manifest 只记**仓库相对逻辑路径**
   （`data/raw/singapore_2024/...`、`data/manifest/singapore_2024.json`），
   **不得**出现 `/Users/levous`、仓库绝对路径或任何 home 绝对路径。
   不同临时 root 下生成的逻辑 provenance 必须一致。
4. **不改数据语义**：17,568 行、signed IGS 原值、USEP ×0.001、SASEA 唯一实际负荷、
   天气 age 0/30、无未来天气、unavailable 四项不伪造 —— 全部保持。

### 11.5 五个问题的修复

1. **revision 语义**：新增 `resolve_materializer_revision()` —— 由
   `git log -1 --format=%H -- scenario/singapore_2024.py scripts/materialize_singapore_2024.py`
   解析（经 Git 校验为 40 位十六进制提交），字段名改为 **`materializer_revision`**，
   **不再使用**随分支 HEAD 漂移的 `code_revision`。**不接受**调用者传入的 revision。
2. **失败原子性**：候选 parquet 先写**同文件系统临时文件**，算出候选 hash 与候选
   manifest 后**先比较再落盘**；顺序固定为「验证 → 构建 → 候选临时文件 → 比较 →
   仅在安全时 `os.replace`」。不一致 → 删临时文件、正式产物**完全不动**；
   一致且正式 parquet 已匹配 → **不重写**；正式 parquet 缺失/损坏 → 仅当候选 hash
   与冻结值相符时**原子恢复**；首次冻结 → 原子替换安装。异常路径由 `finally` 清理临时文件。
3. **路径可移植**：新增 `logical_repo_path()` —— 仓库内文件记**仓库相对路径**
   （`data/raw/singapore_2024/emc_usep_2024.zip`、`data/manifest/singapore_2024.json`），
   仓库外文件记稳定的 `<external>/<文件名>`；**绝不**写入机器绝对路径或 home 路径。
4. **数据语义不变**：见 §11.6 的 parquet 字节同一性证明。
5. **测试标记整改**：slow 由 **27 项降为 1 项**（只剩真实冻结 raw 的全量验收）。
   做法：全年 fixture 与读取结果**模块级缓存**（`cached_valid_fixture()` /
   `cached_valid_frame()`），happy-path 用例共享同一次读取；
