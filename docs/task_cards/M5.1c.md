## 1. 目标

M5.1b 建好了真实采集器，但 `safe_rl_v2/train.py::dry_run_update` 仍**绕开**它：
自己 `policy.act()` + `_clip_action` + `env.step()`，并用 `info.get(..., 0.0)` 兜底、
把 `business_gap` 与 `cost` 相加（**混单位**）。本卡把该入口改为唯一数据来源 =
`collect_rollout` 写出的 contract-v6 buffer，并让采样 RNG 可显式注入。

**本卡不新增 RL 数学**：不实现 PPO ratio/clip、不改动 GAE/乘子语义、
不新增 actor-loss 形式。既有 dry-run 仍只是「闭环可更新」的冒烟验证。

## 4. 禁止项

1. **不实现** PPO ratio/clip、新 actor-loss、熵项；**不重建** GAE 与乘子语义。
2. **不得**声称 M5.2 / M5.3 / M5.4 / M5.5 完成，**不得**把本卡 dry-run 表述为
   「正确 PPO」或任何训练/性能结论。
3. **不得**通过重新播种全局 Torch RNG（`torch.manual_seed`）来「实现」可复现性；
   注入的 RNG 必须是调用方持有的显式对象。
4. **不得**对 `exec_action` 求概率；`old_raw_log_prob` 只作旧策略审计值。
5. **不得**用 `info.get(key, 0)` 或任何默认值伪造缺失的环境字段。
6. **不得**把业务违规量、碳排放量、电费相加或互相顶替。
7. **不得**用 `np.clip` 修改采样动作；越界必须报错。
8. **不得**为保证「可行」而清队列、重置 SOC、跳过任务或放宽任何物理约束。

## 5. 接口约定

### 5.1 `SafePPOPolicy.act(obs, generator=None)`

`generator` 为 `torch.Generator | None`；给定时**只**消耗该 generator，不触碰全局 RNG。

### 5.2 `collect_rollout(..., generator=None)`

- `generator` 透传给 `policy.act`；
- 采集器内**不得**调用 `torch.manual_seed`；
- 返回 stats 增加：
  `env_seed`（`int`）、`policy_rng_source`（`"explicit_generator"` / `"global_torch_rng"`）。

### 5.3 `dry_run_update(...)`

```python
dry_run_update(env, policy, lagrangian, optimizer, *,
               corrector_on=False, corrector_time_limit_s=None,
               steps=8, seed=0, generator=None) -> dict
```

- **唯一采样来源**：`collect_rollout` → `RolloutBuffer`；
- observation / raw_action / reward / 业务违规量 / 碳排放量 / 终止状态**全部**取自
  buffer 的 transition；
- 可导 likelihood =
  `policy.evaluate_raw_actions(buffer.observation, buffer.raw_action)`；
- `exec_action` 不出现在任何损失项；
- 返回值在原键之外增加：
  `buffer`、`stats`、`steps_collected`、`old_raw_log_prob_mean`（审计）、
  `business_violation_sum`、`carbon_emission_sum_kg`、`electricity_cost_sum_sgd`、
  `env_seed`、`policy_rng_source`。

### 5.4 终端语义的唯一修正

bootstrap 项在**终止**步取 0（用 M5.1a 引入的 `terminated` 字段），
这是 `next_observation`/`terminated`/`truncated` 被加入 v6 的直接理由。
**除此之外不改动任何 GAE/目标/乘子语义**——它们原样保留，列为 M5.2/M5.3 重建内容。

### 10.4 完整 payload 的跨进程确定性证据（非仅计数）

probe 输出（`--no-write-run`，三个独立进程逐一比对）：

| 臂 | transition 数 | raw/exec 差异数 | term | trunc | contract | `env_seed` | RNG 来源 | 决策相关 payload sha256 |
|---|---|---|---|---|---|---|---|---|
| corrector 关闭 | 8 | 0 | 0 | 0 | `contract-v6` | 0 | `explicit_generator` | `ba97cab2…34818a` |
| corrector 开启 | 8 | 8 | 0 | 0 | `contract-v6` | 0 | `explicit_generator` | `8de6ec59…f16a0dc` |

**三个独立进程**产出的上述两个 sha256 **完全相同**，`deterministic_repeat_decision_payload_match = true`。
哈希覆盖 payload 的**每个字段的每个值**（transition 每对象 13 个字段），而非计数。

**一处必须如实登记的发现**：corrector 开启时，**完整** payload 的 sha256 跨进程不同
（`84acc08b…` 等）。逐字段排查后确认，差异**只**落在三个墙钟计时审计字段：
`correction_solve_time_s`、`stage_a_solve_time_s`、`stage_b_solve_time_s`。
同一对比下 `raw_action`、`exec_action`、`old_raw_log_prob`、`correction_reason`、
`business_gap`、`stage_a/b_objective`、`stage_a/b_status`、`projection_offset`
**全部逐元素相同**。

因此 probe 同时上报两个指纹：
- `payload_sha256`（含墙钟读数）；
- `decision_payload_sha256`（剔除上述三个计时字段）= 决策与损失真正依赖的内容。

`test_corrector_arm_differs_only_in_wall_clock_audit_fields` 持续守住该不变量，
`test_decision_fingerprint_is_sensitive_to_action_changes` 保证指纹有齿。
**本卡未修改 `planning/` 或 corrector**，故不试图消除墙钟读数。

### 10.7 风险与阻塞

1. **本卡仍不是 PPO**：无 ratio、无 clip、无熵项。`Lagrangian` 与
   `compute_three_value_targets` 仍是 M5.4 占位实现，**列为 M5.2 / M5.3 待重建**。
   dry-run 只证明「真实采集 → 一次更新」闭环可执行，**不构成任何性能或收敛结论**。
2. `safe_rl_v2/models.py` 与 `safe_rl_v2/lagrangian.py` 本卡**未修改**，其语义正确性
   仍待 M5.2 / M5.3 处理；本卡只是把数据来源换成真实 buffer。
3. `Makefile` 的 `train` 目标仍以 `safe_rl_v2/train.py` 作为脚本执行，而该文件现在
