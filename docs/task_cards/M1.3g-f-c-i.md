**解释（如实，不掩饰）**：F3-R2 修复到达激活时机后，24 个 origin × 三档提案的全部
1152 × 3 个 transition 上 `sla_violation_count` **恒为 0**，故按 dh.6「business 取三提案
最小」**实测得到 0**。这与 F4 的服务资格证据**同向**（72/72 达标、期末剩余 0、不可中断中断 0），
但**本卡不把 F4 报告当作预算数据来源**——预算只由本次标定 run 的三档均值按预注册公式得出。
business 乘子的 `scale = max(1, 0) = 1.0` 是**公式自带的下限**，不是人为加的下限；
`business_budget = 0` 意味着 Lagrangian 惩罚对任何 SLA 违规都会触发（严格口径），
本卡据实记录、**不**上抬该值，也不套用旧预算。
