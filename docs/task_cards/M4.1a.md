## 1. 目标

把 `SystemSnapshot` 从「单步简化视图」扩展为足以支撑滚动 24h 联合可行性规划的**具名、单位明确、无未来真值泄漏**的输入契约。本卡**只做契约与 adapter**，不实现/修改 MILP、corrector、PPO 或 reward。

## 2. 边界（允许修改的文件）

- `contracts/models.py`、`contracts/validators.py`、`contracts/__init__.py`
- `planning/snapshot_adapter.py`
- `checkpointing/versioned.py`、`safe_rl_v2/buffer.py`（仅版本常量导入处，若需）
- 对应测试 + 新增 `tests/test_m41a_snapshot_completeness.py`
- 新增 `docs/task_cards/M4.1a.md`（本任务卡）

## 3. 禁止项

- 不实现/修改 MILP、corrector、PPO、reward；
- 不泄露未来真值；不改 `marl/`、`grid_model/`、`legacy/`；
- 不改 contract-v2 之外的既有语义；**契约形状变更故版本升至 `contract-v3`**。

## 4. 命名取舍（须登记）

现有字段 `group_capacity_kw` 实际存放**逐组 work capacity**（来自 `env.model.C_server`），名称带 `_kw` 属单位误标。
其消费者 `planning/model.py`、`planning/corrector.py`、`safe_rl/corrector.py` **不在本卡授权范围内**，
故**不重命名**，只把声明单位更正为 `work-units` 并在文档中标注，避免破坏未授权模块。
新增规划所需的功率线性化字段（见 §5.6）。

## 5. 必须提供的规划输入

1. **时间**：`step`、`delta_t_hours`、`planning_horizon_steps`
2. **储能**：`soc_kwh`/`soc_min_kwh`/`soc_max_kwh`/`soc_capacity_kwh`、`bess_charge_power_max_kw`/`bess_discharge_power_max_kw`、`bess_charge_efficiency`/`bess_discharge_efficiency`、`bess_degradation_cost_per_kwh`
3. **接入与基础负载**：`access_limit_kw`、`base_idc_power_forecast_kw`（按预测温度计算）
4. **预测**：`price`/`pv`/`wind`/`temperature`/`carbon`/**任务到达**（`ScenarioBundle` 增 `arrival_forecast`），均 `[t, t+cutoff)` 可见窗口 + horizon 尾部零填充
5. **任务**：`remaining_work`、`deadline`、`priority`、`status`、`max_rate_work_per_step`；仅**已到达**任务进入规划，未来到达只用聚合预测
6. **组**：逐组 work capacity + 规划线性近似功率字段 `group_power_coeff_kw_per_work`、`group_power_upper_kw`，
   并带 `power_approximation_note`（"规划近似，执行前后需由环境物理链复核"）

## 6. 契约版本

`CONTRACT_VERSION_ID`: `contract-v2` → **`contract-v3`**；v2 / 无版本 / 旧 obs_dim 的 checkpoint 必须显式拒绝（唯一版本源仍为 `contracts.__init__`）。
`marl/` 继续标注为**受保护旧基线、与新契约不兼容**，不改动。
