## 1. 目标

测量**真实**的 H 步两阶段 MIP corrector 性能与不同时间预算的 timeout 行为；
将**无 tracing 的性能计时**与**内存采样**彻底分离。

## 3. 禁止事项

- 不修改 `envs/`、`planning/model.py`、`planning/corrector.py`、`corrector_wrapper.py`、
  `contracts/`、`safe_rl` PPO/buffer、`marl/`、`grid_model/`、`legacy/`；
- **不擅自写入 corrector 默认预算**；
- **不把 benchmark 数值写成正式实验结论或 RL 训练吞吐结论**。

## 4. probe 改造

- **正常计时区间绝不启动 `tracemalloc`**；
- 内存采样作为**独立 memory-only pass**；
- 输出字段必须区分 `timing_without_tracemalloc` 与 `memory_with_tracemalloc`；
- 保留 LP、MIP、projection 的规模、阶段耗时、总耗时、预算、timeout 数。

## 5. benchmark

`scripts/benchmark_corrector.py`：

- `perf_counter` 计时；**固定 warm-up 后**，多 seed、多 episode；
- 分别测量 原始 `env.step`、`wrapper.step`、corrector 总耗时、阶段 A、阶段 B；
- 预算矩阵固定为 **0.01 / 0.02 / 0.05 / 0.10 / 0.25 秒**；
- **正常接入**与**紧接入/储能压力**各测一组；
- 输出 JSON：`mean`、`median`、`p95`、`max`、`steps/s`、`timeout_count`、`timeout_rate`、
  零动作回退数、`business_gap` 汇总及**测量口径**。

## 6. 结果要求

- **timeout 是安全零动作回退，不得记为求解成功**；
- 输出「候选预算比较表」，**只报告** `timeout_rate`、`p95`、业务缺口、吞吐；
- **不自动选 production default**；明确供后续 **M5/M9 人工配置选择**。
