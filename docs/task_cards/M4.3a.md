## 5. 模型

- 时间集合 `k = 0..H-1`，`H = planning_horizon_steps`。
- 分配 `A[i,g,k] >= 0`；每任务每步 `sum_g A <= max_rate_work_per_step`；每组每步 `sum_i A <= group_work_capacity[g]`；每任务全时域 `sum_{g,k} A <= remaining_work`。
- 期限：deadline 落在时域内的任务建 `deadline_slack`，不足时显式输出缺口，不伪造完成。
- 功率：`P_idc[k] = base_idc_power[k] + sum_g(coeff[g] * sum_i A[i,g,k])`（仅用规划近似字段，结果标 `power_approximation_used=True`）。
- 能源：`0 <= P_grid <= access_limit`；`pv_used <= pv`；`wind_used <= wind`；
  `P_grid + pv_used + wind_used + discharge = P_idc + charge + curtail`；禁止反送电。
- 储能：`SOC[k+1] = SOC[k] + eta_c*charge*dt - discharge/eta_d*dt`，SOC/充放功率硬约束。
- 目标：`电费 + 退化成本 + 业务 slack 罚项`，三项均 SGD 且分别输出。

## 6. 失败分类

`none` / `base_shortage`（基础负载 + 可再生 + 最大放电仍无法满足接入约束）/ `deadline_shortfall` / `solver_failure`。
