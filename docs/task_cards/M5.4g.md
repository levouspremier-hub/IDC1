## 1. 缺陷（M5.4f 接线错误）

`planning/model.py` 有**三个** `scipy.optimize.milp` 调用点：

| # | 行 | 所在函数 | 谁在用 |
|---|---|---|---|
| 1 | ~620 | `_solve_time_indexed`（`backend == "mip"` 分支） | `solve_time_indexed_mip` 等 |
| 2 | ~1030 | `solve_time_indexed_mip_raw_projection` **阶段 A** | **`correct()`** |
| 3 | ~1094 | `solve_time_indexed_mip_raw_projection` **阶段 B** | **`correct()`** |

M5.4f 把 `deterministic_mip_options` 接到了 **#1**，而 corrector 实际走的是 **#2/#3**。
后者的 `_options()`（~1008）仍然只返回 `{"time_limit": rem}`：

```python
def _options() -> dict:
    rem = _remaining()
    return {} if rem is None else {"time_limit": float(rem)}   # ← 没有 random_seed / parallel
```

**后果（必须如实登记）**：

- M5.4f 的改动**对 corrector 路径没有任何作用**；
- 因此 M5.4f 卡 §9.3 声称的「修复效果」（0.05 s 单次调用 6/6 一致、
  与 2 s 解相同、rollout 级 6/6 reproducible）**不能归因于该改动** ——
  那些测量没有对照到任何实际生效的变更，属**未受控的观察**；
- M5.4f 卡关于**根因**的表述（并据此判定「求解路径已固定」）**同样失效**，
  需在 M5.4f 卡追加勘误。

**M5.4 状态维持 blocked**，等待本卡接线完成后**重新测量**。

## 4. 实现要求

1. raw projection 的 **Stage A 与 Stage B 都必须**通过
   `deterministic_mip_options(time_limit_s=remaining_budget)` 构造 options。
2. **保持原有全局 deadline 语义**：两阶段仍共享同一个 wall-clock 总预算；
   **只能替换 options 构造**，不得改变 remaining-budget 算法。
3. `time_limit_s=None` 时，两阶段仍必须收到 `random_seed=0`、`parallel=False`，
   仅不含 `time_limit`。
4. 用**运行时 spy** 证明 `correct()` 的真实 raw projection 两阶段都调用该函数
   （不能只用 AST 或字符串搜索）。
5. probe 的 solver evidence 必须**从同一 options 函数导出**，记录
   `random_seed` / `parallel` / `time_limit`；不得再只报 `time_limit`。
