## 1. 目标

1. **泄漏门禁**：用真实 `IDCPriceEnv20D` 证明当前时刻可见窗口之外的未来真值
   （price / temperature / lambda / PV / wind / carbon）被逐项突变后，
   当前 `observation`、`raw_action`、`old_raw_log_prob` **逐位不变**；
   并证明改动**窗口之内**的值时 observation **会**变化（反例，防恒真）。
2. **可复现性**：corrector **关闭** 与 **正常预算开启** 两种模式，
   在两个独立 Python 进程中用相同 seed 得到**逐位一致**的语义摘要
   （排除纯耗时字段）。

**⚠️ 已登记的 blocker**：**紧预算**下的跨进程可复现性**不成立**（见 §3）。
本卡**不**对紧预算声称稳定；只登记并给出实测证据。

## 3. 已登记的 blocker：紧预算跨进程**不可复现**（实测）

corrector 的 `CorrectorWrapper` 由**墙钟预算**驱动：时限内未收敛的 MILP 会返回
另一组**仍然经过物理校验**的投影。因此当预算处于「有时够、有时不够」的区间时，
exec 决策会随机器负载变化。

实测（同一份代码、同一 seed、6 路 CPU 争用、各 4 个独立进程；
比较**排除** `correction_solve_time_s` / `stage_a_solve_time_s` / `stage_b_solve_time_s`
后的语义摘要）：

| `corrector_time_limit_s` | 各进程摘要 | 相异数 | 首步 `correction_reason` |
|---|---|---|---|
| `0.003` | `d9bc5cf814ff` ×4 | 1 | `timeout`（恒超时 → 恒返回边界动作，**确定**） |
| `0.005` | `d9bc5cf814ff` ×3、`aac1b5c02365` ×1 | **2** | `timeout` |
| `0.010` | `b0a030b222c1` ×3、`a422ce8a226b` ×1 | **2** | `timeout` |
| `0.020` | `7620deab5d68` ×2、`99a626f6ad58`、`a193f03922f7` | **3** | `timeout`（其中一个进程为 `none`，即**收敛**） |

**结论（blocker）**：

- **紧预算**（处于「有时收敛、有时超时」的区间）下，跨进程逐位可复现**不成立**；
- **极紧预算**（如 `0.003`，恒超时）反而确定 —— 因为输出退化为固定的已验证边界动作；
- 本卡**不**为紧预算编写「断言稳定」的测试；**不得**靠重试挑选成功结果。
- 这与 M5.1c 的实测一致（当时记为「只差墙钟字段」是在**负载稳定**窗口内的观测；
  跨负载条件时连决策都可能不同）。

**为什么不在本卡修复**：消除该不确定性需要改变 `planning/` 的求解器策略
（例如固定求解路径或改为确定性 MIP），**超出本卡允许范围**，且会改变研究语义。
故按任务卡要求**登记为 blocker 并停止**对紧预算稳定性的一切声称。

## 4. 禁止项

1. 不改 env 物理语义、`planning/`、动作维度、raw/exec 概率记录。
2. **不得**用放宽 time limit、跳过 corrector 或忽略 timeout 来伪造可复现。
3. **不得**把 wall-clock elapsed time 纳入跨进程逐字节比较。
4. **不得**为紧预算声称稳定，也不得重试挑选取样。

## 5. 测试设计

**夹具**：`IDCPriceEnv20D(task_seed=0, server_seed=0, forecast_seed=300000)`；
policy 权重由 `torch.random.fork_rng` + 固定 seed 构造；采样用显式
`torch.Generator`。`forecast_cutoff = 4`，故可见窗口为 `[0, 4)`。

| # | 测试 | 标记 |
|---|---|---|
| 1 | 六类未来真值（`price_t`/`T_amb`/`lambda_t`/`pv_t`/`wt_t`/`carbon_factor_t`）在 `>= cutoff` 处突变 → observation 逐位不变 | `leakage` |
| 2 | 同上突变 → `raw_action` 与 `old_raw_log_prob` 逐位不变 | `leakage` |
| 3 | 改动窗口**之内**的值 → observation **变化**（反例，证明 #1 非恒真） | — |
| 4 | corrector 关闭：`exec_action` 逐元素等于 `raw_action`，且 `correction_info` **不含**任何 solver 成功字段 | — |
| 5 | corrector 开启：`raw_action` 与 `old_raw_log_prob` 始终保留；`exec_action` 只来自 `info["exec_action"]` | — |
| 6 | 预算**语义负荷**：恒超时预算与收敛预算给出**不同** exec —— 这是 blocker 的确定性机制证据 | — |
| 7 | 跨进程（corrector 关闭）语义摘要逐位一致 | `slow` |
| 8 | 跨进程（corrector 开启、**正常**预算 `0.05`）语义摘要逐位一致 | `slow` |
| 9 | 紧预算**不**被声称稳定：断言 blocker 已登记且该模式**没有**「断言相等」的测试 | `slow` |

跨进程做法：用 `sys.executable -c <脚本>` 在**独立进程**中跑 `collect_rollout`，
输出排除墙钟字段的语义 sha256；测试比较两个进程的输出。
