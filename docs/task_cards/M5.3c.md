## 1. 缺陷（M5.3a 遗留）

M5.3a 的 `load_state_dict()` 校验了**类型与静态定义**（版本、聚合口径、约束集合、
单位、budget/lr/max、multiplier 范围、log 有限性与长度），但**没有校验状态内部的自洽性**：
它只要求每个字段「单独合法」，不要求「整体上能由 `update()` 产生」。
于是一批**形态合法但物理上不可能**的 contract-v7 payload 会被静默接受，
恢复出一组永远不会出现的乘子历史。

### 1.2 为什么这些状态不可能由 `update()` 产生

`update()` 是唯一改变这些字段的入口，且它的形态固定：

```python
candidate = state.multiplier + state.learning_rate * (estimates[name] - state.budget)
state.multiplier = float(min(max(candidate, 0.0), state.max_multiplier))
state.updates += 1
state.log.append(state.multiplier)
...
self._updates += 1
```

因此**恒等成立**的不变量：

| 不变量 | 理由 |
|---|---|
| `0 ≤ log[i] ≤ max_multiplier` | 写入 `log` 的值就是被 clamp 过的 `multiplier` |
| `log[-1] == multiplier`（`updates > 0` 时） | `append` 发生在赋值之后，且此后只有再调用 `update()` 才会改变 |
| `constraint.updates == 顶层 updates` | 两者在**同一次**调用中各加 1，且初值都是 0 |
| `len(log) == updates` | 每次调用恰好 append 一项（M5.3a 已校验） |
| `updates == 0` ⇒ `multiplier == 0 ∧ estimate == 0 ∧ log == []` | 构造后的初始状态；`estimate` 只在 `update()` 内被写 |

本卡把上述不变量变成 `load_state_dict()` 的**强制拒绝条件**。

## 3. 禁止项

1. **不得提升 contract 版本**：`state_dict()` 的序列化 schema **完全不变**，
   仍是 `contract-v7`；本卡只是拒绝原本就无效的 v7 状态。
   （若升到 v8，会把「修复前落盘但恰好合法的 v7 状态」也一并作废，那是**过度**破坏。）
2. **不得兼容旧 v6 或任何旧形态**：M5.3a 的拒绝规则保持原样。
3. **不得改动 actor objective 或乘子更新数学**。
4. **不得部分写入**：所有校验必须在临时结构中完成，失败时 `self` 逐位不变。

## 4. 必须新增的拒绝规则

| # | 条件 | 违反时 |
|---|---|---|
| R1 | 每个 `log[i]` 有限且 `0 ≤ log[i] ≤ max_multiplier` | `ValueError` |
| R2 | `updates > 0` 时 `log[-1] == multiplier`（严格相等） | `ValueError` |
| R3 | 每个 `constraint.updates == 顶层 updates` | `ValueError` |
| R4 | `updates == 0` ⇒ `multiplier == 0 ∧ estimate == 0 ∧ log == []` | `ValueError` |

R4 的三个子条件都要**分别**报错，便于定位。

合法边界（`multiplier` 恰为 `0` 或 `max_multiplier`；`log` 恰含这两个值）
**必须继续被接受**。
