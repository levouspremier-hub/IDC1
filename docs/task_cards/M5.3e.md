## 1. 缺陷（M5.3a 遗留）

`update()` 只校验信号的**有限性**，不校验**非负性**；`load_state_dict()` 只校验
`estimate` 的有限性，同样不校验非负性。于是物理上不可能的量会被静默接受：

- `business` 的单位是 `violation_task_steps` —— **违规任务·步计数**；
- `carbon` 的单位是 `kgCO2e` —— **排放质量**。

两者都**不可能为负**。负值只能来自上游缺陷（例如字段接错、单位换算符号写错、
或把「碳信用/负电价」之类的量误接进约束通道）。接受它会让乘子被反向驱动
（低于预算即视为「表现良好」，从而**奖励**违规），这是静默的语义错误。

## 3. 禁止项

1. **不得提升 contract 版本**：序列化 schema 不变，仍为 `contract-v7`。
2. **不得把负信号裁剪为 0**（或取 `abs`、`max(0, x)` 等）：必须**明确拒绝**。
   裁剪会把上游缺陷掩盖成「合法但被改写的数据」，并让乘子按错误的量更新。
3. **不得只检查均值**：必须逐 transition 校验。
4. **不得让 `update()` 在校验失败时留下任何痕迹**。
5. 不改 actor objective、乘子更新数学或物理环境。

## 4. 必须新增的规则

| # | 条件 | 违反时 |
|---|---|---|
| D1 | 每个 transition 的 `business` 信号有限且 `>= 0` | `ValueError`（指明约束名、下标、值） |
| D2 | 每个 transition 的 `carbon` 信号有限且 `>= 0` | 同上 |
| D3 | 任一约束信号不合法时，`update()` **不得**改动**任何**约束的
`estimate` / `multiplier` / `updates` / `log`，也不得改动全局 `updates` | 原子性 |
| D4 | `load_state_dict()` 拒绝负 `estimate`（拒绝仍原子） | `ValueError` |

### 4.1 共享校验（供 M5.3f 复用）

新增**纯函数**（不接触任何实例状态）：

```python
validate_constraint_signals(batch_signals, expected) -> dict[str, float]
```

- 校验 Mapping 类型、键集合、逐约束「序列而非标量」、一维、非空、有限、**非负**；
- 返回每约束的 per-transition mean，供调用方使用；
- `update()` 与（M5.3f 的）训练预检**共用同一份规则**，不得各写一套。
