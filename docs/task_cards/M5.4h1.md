## 1. 缺陷（M5.4h 遗留，已在 `runs/m54h_matrix/hogs4/` 上实测复现）

### 1.1 审计表缺字段、缺「未执行 Stage B」行

```
列: [budget_s, corrector_reason, elapsed_s, mip_dual_bound, mip_gap,
     mip_node_count, node_cap_injected, options_json, pid,
     remaining_deadline_s, stage, status, step, success]
含 unavailable_fields: False      含 digest: False      含 skipped: False
stage 取值: ['A', 'B']
```

`unavailable_fields` 与 `digest` **未落盘**；且只记录**实际执行**的调用 ——
某步若只跑了 Stage A（A 失败/超时），该步**没有** Stage B 行，
审计表静默少行，无法区分「B 未执行」与「B 未记录」。

### 1.2 负载事实自相矛盾

```
config.load_injected   = False                     ← 硬编码
config.load            = {'mode': 'hogs', 'concurrency': 4, 'program': ...}
report.provenance_note = "每个 digest 来自一个独立 Python 进程；未注入 CPU 负载…"
```

在 **hogs 口径**下同时出现「未注入 CPU 负载」与「load.mode=hogs」，
任务卡 §9.6 的归因正建立在负载对比之上 —— 账本自相矛盾会直接动摇结论。

### 1.3 缺 `release_gate`：0.05 s 不稳定却写 `success`

```
manifest.status              = success
report.attribution.conclusion = wall_clock_budget_dominant
0.05s distinct                = 2          ← 默认预算跨进程不一致
```

`status` 由 `attribution` 推导（`overall.blocked = conclusion != wall_clock_budget_dominant`），
于是「归因成立」被误当成「默认预算可发布」。**归因与发布门禁是两个概念，必须分开。**

### 1.4 节点上限臂未做「替代语义」

```
对照臂 options keys: ['parallel', 'random_seed', 'time_limit']
```

节点上限只是**叠加**在 wall-clock 之上，`time_limit` 仍在 ——
因此 M5.4h §9.5 混了一个结论：它测的是「节点上限 + wall-clock」，
**没有**测「只用节点上限、停用 wall-clock」这一真正的替代语义。

## 4. 实现要求

### 4.1 逐阶段字段全量落盘 + 显式 skipped 行

每个 `step × {A, B}` 必须**恰好一行**，字段：
`options`（`options_json`）、`status`、`success`、`message`、`elapsed_s`、
`remaining_deadline_s`、`mip_node_count`、`mip_dual_bound`、`mip_gap`、
`unavailable_fields`（JSON 串）、`corrector_failure`、`corrector_reason`、`digest`。

**未执行的 Stage B 必须有显式行**：`skipped=true`、`skip_reason=<原因>`、
数值字段为 `null`。**不得静默少行。**

### 4.2 负载事实统一

`load_injected` 由 `load["mode"] == "hogs"` **推导**，并在
`config` / `report` / `summary` 中一致；`provenance_note` 也按口径生成
（hogs → 明确「已注入受控 CPU 负载」；none → 「未注入」）。
`manifest.command` 必须含实际负载参数。四者**不得互相矛盾**。

### 4.3 `attribution` 与 `release_gate` 分离

```python
release_gate = {
  "default_budget_s": 0.05,
  "observations": [...],     # 来自 modes.on 与矩阵 0.05 档
  "blocked": bool,           # 任一 0.05 观测 distinct > 1
  "all_qualifying": bool,    # 每个观测都满足 processes>=6 且 steps>=8
  "reason": str,
}
```

**只要默认 0.05 s 任一合格矩阵出现 `distinct>1`**：
`release_gate.blocked=true`、`run manifest.status="failed"`、进程退出码非 0 ——
**即使 `attribution=wall_clock_budget_dominant` 也不得写 `success`**。

### 4.4 节点上限「替代语义」臂（与既有臂分开）

- 既有臂：`node_cap_with_wall_clock`（保留 `time_limit`，仅叠加 `mip_max_nodes`）；
- **新臂**：`node_cap_alternative_semantics` —— 注入 `mip_max_nodes` 并
  **显式移除 `time_limit`**，记录 `wall_clock_disabled_in_probe=true`。

两臂**分开命名、分开产物（不同 run_id）、分开结论**，禁止合并为一个结论。
均只在 probe runtime wrapper 内生效。

### 4.5 新产物

`runs/m54h1_*`；每组 **≥6 独立进程、8 步**；至少覆盖
`hogs4`、`hogs8`、`0.05 s`、`0.25 s` 与**节点替代语义候选**。

### 4.6 结论如实区分

- `0.25 s` 只能称作**本机候选值**（machine-local），**不得**声称跨机器保证；
- 节点上限**只有**在替代语义臂稳定时才可称为候选；
- **M5.4 默认状态仍为 blocked**，直到用户明确批准预算策略。
