## 1. 目标

1. 让 PV/wind/carbon 的**运行时**归一化真正使用冻结/声明参考值，不再与当前序列峰值比较；
2. 建立 `contracts.CONTRACT_VERSION_ID` 作为**唯一**版本源（contracts / checkpointing / buffer 三处导入，禁止各自硬编码）；
3. 修正 M3.10b 遗留的旧文档描述（「6 组、280 维」）。

## 2. 已发现的问题（改造前）

| 问题 | 现状 |
|---|---|
| 运行时参考值被峰值污染 | `self.pv_ref_kw = max(float(pv_ref_kw), pv_peak_kw, 1e-6)`（wind/carbon 同）→ 参考值随数据序列变化，等价于按 episode 动态重算 |
| 版本字符串三处硬编码 | `contracts/models.py:20`、`checkpointing/versioned.py:15`、`safe_rl_v2/buffer.py:13` 各自写死 `"contract-v2"` |
| 旧文档 | `_get_forecast_features` / `_get_obs` docstring 仍写「6 组」「280 维」 |

## 4. 禁止项

- 不改 `marl/`、`grid_model/`、`legacy/`；
- 不根据 price/PV/wind/carbon 当前序列的 max/min/分位数动态重算任何参考值；
- 不把 `contract-v2` 无意义升级为 v3（本卡只修唯一来源与运行时使用）。

## 5. 版本策略

`CONTRACT_VERSION_ID = "contract-v2"`（定义在 `contracts/__init__.py`），`ContractBase.schema_version` 默认值、`checkpointing.CURRENT_CONTRACT_VERSION`、`safe_rl_v2.buffer.CONTRACT_VERSION` 均**导入**该常量。

## 6. `marl` 遗留契约（仅文档记录）

`marl/` 旧链内部仍按「6 组前瞻特征 / obs 280」的旧契约工作，属**受保护旧基线，与新链 `contract-v2` 不兼容**；按红线不修改 `marl/`，本卡仅在文档中记录，不声称其已兼容。
