## 1. 目标

让环境 observation 与 `planning.snapshot_adapter` 对 `forecast_cutoff` 使用同一个、可测试的「当前时刻起可见窗口长度」定义，杜绝 off-by-one 未来信息泄漏。

**统一定义**：`forecast_cutoff` = 当前时刻起、含当前时刻在内的可见预测点数。时刻 `t` 的可见区间为 `[t, t + forecast_cutoff)`，首个不可见真值下标为 `t + forecast_cutoff`。

## 2. 已发现的不一致（改造前）

| 位置 | 现定义 | 可见区间 |
|---|---|---|
| `envs/idc_price_env.py::_get_forecast_features` | `visible[: t + cutoff + 1] = 1` | `[0, t + cutoff]`（从 0 起、含端点） |
| `planning/snapshot_adapter.py::_visible_window` | `series[t : t + cutoff]` | `[t, t + cutoff)` |

两者既起点不同（0 vs t），端点也不同（含 `t+cutoff` vs 不含）。env 因此在 `t>0` 时暴露了 `t + cutoff` 这一未来点，且把已过时段一并暴露。
