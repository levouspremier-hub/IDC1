## 1. 缺陷（M5.4a 遗留，已实测复现）

### 1.1 `write_run` 允许失败 run 覆盖成功 run

```python
if manifest_path.exists():
    existing = json.loads(manifest_path.read_text(encoding="utf-8"))
    if existing.get("status") == "success" and status == "success":   # ← 只拦 success→success
        raise FileExistsError(...)
```

实测（`bd0d318`）：

```
=== 1. 成功 run 被同 id 的失败 run 覆盖 ===
[ACCEPTED-ERROR] 失败 run 覆盖了成功 run
    manifest.status 现在 = failed
    被改写的文件 = ['config.yaml', 'manifest.json', 'metrics.parquet', 'report.json']
```

**一次失败的复跑会销毁此前成功 run 的全部产物**，并把 manifest 改成 `failed`。
这违反 IMPLEMENTATION_PLAN §1.4「同 run id 不覆盖已有成功结果」，且**不可恢复**。

### 1.2 直接调用 `write_run` 同样可被 `status=failed` 覆盖

```
=== 2. 直接调用 write_run：success 存在时 status=failed ===
[ACCEPTED-ERROR] status=failed 覆盖了 success（当前实现只拦 success→success）
```

### 1.3 `manifest.command` 不是完整的调用账本

```
command = python -m safe_rl_v2.train --steps 2 --seed 0 --corrector off --run-id cmd --synthetic-smoke
缺失参数 = ['--base-dir', '--task-seed', '--server-seed', '--forecast-seed', '--horizon']
```

命令由字符串手工拼接，**遗漏了决定复现性的关键参数**（三个 env seed、horizon、
base-dir、corrector 预算）。照此命令无法重放该 run，manifest 的「命令」字段形同虚设。

### 1.4 默认（真实数据）路径产生误导性 run_id

```
=== 4. 默认（真实）路径的 run_id 是否误导 ===
    默认阻塞路径产生的目录 = ['train_synthetic_s0_20260914T064030Z']
```

`_unique_run_id` 无视场景类型一律写成 `train_synthetic_*`。默认路径**根本没有使用**
合成数据（它是因 M1.2 阻塞而失败），却留下一个声称 synthetic 的目录名 ——
既不准确，也会被误读。

## 3. 禁止项

1. **不得**通过把失败静默吞掉来「避免覆盖」（例如失败时什么都不写却不报告）。
2. **不得**让失败的 run 覆盖已有成功 run —— 任何状态都不行。
3. **不得**把「保留了成功结果」写成「失败 manifest 已写入」。
4. **不得**升级 `contract-v8`：这是运行产物完整性修复，非模型/schema 变化。

## 4. 实现要求

### 4.1 writer 层（强约束）

任何**已有成功 manifest**都不可被**任何**后续状态覆盖：

```python
if existing.get("status") == "success":
    raise FileExistsError(f"run {run_id} 已存在成功结果，不得被 status={status} 覆盖")
```

### 4.2 处理语义（必须明确记录）

| 情形 | 语义 |
|---|---|
| 空目录 / 不存在 | 正常写入 |
| 已有 **success** | **拒绝任何写入**（含 failed）→ `FileExistsError` |
| 已有 **failed**，新 **failed** | 允许（同 id 复跑重试） |
| 已有 **failed**，新 **success** | 允许（修好原因后重跑） |
| 合成 dry-run | `status=success`，自我标注 `synthetic=true` / `dry_run_only=true` |
| 默认 M1.2 阻塞 | `status=failed`，run_id 前缀为 `train_real_*`（**不得**写 synthetic） |
| 失败且 run_id 撞上已有成功 run | **保留成功 run**，抛出明确冲突错误并返回专门的退出码；**不得**声称已写失败 manifest |

### 4.3 命令账本

`manifest.command` 必须由 **argv 列表 + shell 安全转义**（`shlex.join`）构造，
且**结构上不可能遗漏**任何 CLI 参数：模块内维护一张
`(flag, dest, kind)` 清单，并用测试断言它**覆盖 `build_parser()` 的全部 action** ——
将来新增 CLI 参数而忘了加进清单时，测试会失败。

### 4.4 run_id 前缀

`_unique_run_id(base_dir, seed, *, kind)`：
`kind="synthetic"` → `train_synthetic_s{seed}_{stamp}`；
`kind="real"` → `train_real_s{seed}_{stamp}`。
