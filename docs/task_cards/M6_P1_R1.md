## 3. 三项缺陷（复审）

1. **资格口径不一致**：`classify_tasks` 把「提前完成但截止时点在 episode 外」的任务
   计入 `on_time_completed_*`（分子），而分母 `due_in_episode_*` 只数**截止时点在
   episode 内**的任务 ⇒ 比率可以 **> 1**（1 个到期 + 1 个未到期早完成 = 2/1）。
2. **物理违规未进入比较资格**：接入 / SOC / 充放互斥 / 守恒任一违规时，
   仍可能得到 `service_qualified is True` ⇒ 可进入「同等服务成本/碳比较」。
3. **受控 run 的 manifest 缺来源账本**：`dependency_lock_hash` / `data_hash` /
   `scenario_hash` 均为 `null`。

## 4. 先红测试（**必须先于实现提交**）

1. **口径反例**：构造「1 个本 episode 到期任务（按时完成）+ 1 个提前完成但
   截止时点在**下一个** episode 的任务」⇒ 断言
   `0 <= on_time_task_rate <= 1`、`0 <= on_time_work_rate <= 1`，
   且**分子与到期分母同口径**；同时断言五个分类计数之和 == 已到达任务数。
2. **物理违规门禁**：无违规 ⇒ 可达 `True`；**单项违规**（接入 / SOC / 充放互斥 /
   守恒，逐项各一个用例）⇒ **不得**出现 `True`，且说明文字给出违规原因。
3. **manifest 来源账本**：受控 run 的 manifest 必须写入**实测且可重算**的
   `dependency_lock_hash` / `data_hash` / `scenario_hash`，三个值可用
   `uv.lock` 与已验签来源**独立重算并一致**。
