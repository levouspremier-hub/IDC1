## 4. 失败分类

新增 `FAILURE_TIMEOUT = "timeout"`，与 `solver_status` 一一对应：

| `solver_status` | `failure_class` | 处理 |
|---|---|---|
| `optimal` | `none` / `deadline_shortfall` | 现有成功路径不变 |
| `time_limit` | **`timeout`** | 立即零执行返回，**不调用诊断**（见 §5） |
| `infeasible` | 保留现有基础负载诊断分类逻辑 | 不变 |
| `solver_failure` | `solver_failure` | 不变 |

**不得把 timeout 混入 `solver_failure`。**

## 5. timeout 语义

MIP 返回 `time_limit` 时：

- **立即**返回零执行量与显式全部剩余业务缺口（`allocation=0`、`business_shortfall_work=Σ remaining_work`）；
- **不调用 `diagnose_base_feasibility()`**——不得为了失败分类再启动第二次求解；
- 返回 `backend="mip"`、`n_integer_variables=H`；
- 成本、SOC、电力流**均不得伪造为已执行结果**（`electricity_cost_sgd=0`、`p_grid_kw` 全 0 等）。

## 6. 测试策略

1. 用 `monkeypatch` 模拟 `scipy.optimize.milp` 返回 `status=1`，锁定 timeout 行为；
2. 模拟未知/失败状态（如 `status=4`），锁定 `solver_failure` 分支；
3. 以上均为**求解器边界单元测试**，不依赖机器速度或偶然的真实超时。

## 7. LP/MIP 对比测试重写

- 弃用「若 LP 恰好同步充放则断言」的空覆盖写法；
- MIP 在储能压力场景**逐步**验证 `charge[k]·discharge[k] ≈ 0`；
- LP 验证 `n_integer_variables == 0`、`backend == "lp"`，并明确标记为**不可执行松弛**；
- 保留 MIP 整数变量数 == H、目标值不优于 LP 下界的测试。

**关于 LP 同步充放的数学说明（须如实写入本卡）**：
在严格正退化成本（默认 `0.02 SGD/kWh`）与有损往返（`eta_c < 1`、`eta_d < 1`）下，
同一步同时充放会使 `charge` 与 `discharge` 在能量平衡中部分抵消，净效果是**损失电池能量并额外支付退化成本**；
令两者同时为 0 是严格更优解，故 **LP 最优解不会出现同步充放**。
因此本卡**不伪造 coflow 场景、不修改物理参数**来制造同步充放；
改以**结构性证据**说明松弛真实存在：LP 结果中不含任何 `storage_excl_*` 约束行，而 MIP 结果含 `2H` 条。
