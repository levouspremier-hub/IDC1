## 4. 修复要求

1. **raw baseline 与 wrapper 同场景**：`access_limit_kw`、`bess_soc_init`、`horizon`、action 完全一致；
   每个 scenario 的 JSON 输出 `scenario_config`（实际使用的配置）。
2. **替换 `optimal_count`**：
   - `executable_candidate_count`：`correction_reason` ∈ {`none`, `deadline_shortfall`}；
   - `timeout_count`：仅 `timeout`；
   - `non_timeout_failure_count` + `failure_counts`：`base_shortage`、`solver_failure`、`proposal_invalid` 及**任何未知失败原因**；
   - `zero_action_fallback_count`：实际发送零动作的失败回退次数；
   - `unsafe_failure_action_count`：失败类别却发送非零动作 → **必须为 0**；
   - **不得再输出 `optimal_count`**。
3. **计数恒等式**（每个预算/场景）：
   `n_steps = executable_candidate_count + timeout_count + non_timeout_failure_count`；
   且 `timeout_count` 必须归入 `failure_counts`；**timeout 不计为 executable candidate**。
4. 重跑完整 benchmark，在 M4.6a1 给出**完整新表**；M4.6a.md 仅追加醒目勘误。
