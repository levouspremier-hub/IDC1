## 4. 实现要求

1. **唯一来源**：`planning/corrector.py` 定义
   `PRODUCTION_CORRECTOR_TIME_LIMIT_S = 0.25`；其余四个入口 `import` 它，
   不得各自定义 0.25。
2. **默认路径解析为 0.25**：synthetic train `--corrector on` 无预算、`make smoke`、
   `probe_rollout_deterministic.py`、`probe_corrector_repro.py`。
3. **显式 override 保真**：显式 `--corrector-time-limit-s 0.05` /
   `--corrector-time-limit 0.05` 必须实际用 0.05，绝不静默替换为 0.25。
4. **provenance 三字段**：config/report/manifest 记录
   `production_corrector_time_limit_s`、`effective_corrector_time_limit_s`、
   `corrector_time_limit_source`；source ∈ {`production_default`,
   `explicit_override`, `disabled`}，且**由「是否显式给出预算」决定**，
   不是由数值是否等于 0.25 决定。
5. **命令账本保真**：未传预算时 `manifest.command` **不得**伪造显式预算参数；
   显式传时必须包含该参数。
6. **release gate 只认生产默认**：`passed = evaluated and all_qualifying and not blocked`
   （M5.4h2 的 fail-closed 规则保留）。只有来源为 `production_default` 的观测才能进入
   gate；显式 override 观测进入独立的 `override_observations`，如实记录但**绝不**
   参与生产 release 判定。未测量 / 样本不足 / 不稳定一律 `manifest=failed`、`exit!=0`。
7. **Stage A/B 共享一个 0.25 s deadline**：用 runtime spy 证明（见 §6 验收）。

### 12.1 第三次审核未通过的三个问题

#### 问题 1：容器型 provenance 在 set 构造时泄漏 `TypeError`

`_aggregate` 尾部用集合推导汇总来源与预算：

```python
sources = sorted({b["corrector_time_limit_source"] for b in batches}, ...)
production_caps = {b["production_corrector_time_limit_s"] for b in batches}
```

若三处 provenance 是**相同**的 `list`/`dict`（三处恒等，因此前面的逐字段比较**不会**报错），
集合构造会因为不可哈希而抛异常并**泄漏给调用方**。实测：
`list` → `TypeError: unhashable type: 'list'`；`dict` → `unhashable type: 'dict'`。

#### 问题 2：非字符串 digest 被 `str()` 后错误放行

`_check_batch` 用 `digests.extend(str(d) for d in observed)` 收集摘要，
`str()` 把错误类型「修正」成看似合法的证据。实测：三个批次的 digests 全为
`[1, 1, 1, 1, 1, 1]`（非字符串、非 SHA-256）时，字符串化后六个值相同 →
`aggregate_distinct=1` → **`passed=True`、`failures=[]`**。

#### 问题 3：`processes`/`steps`/`status` 的宽松 `int()` 会截断非整数

`_coerce_int` 直接 `int(value)`，于是非整数被静默截断或类型矫正。实测：

| 篡改 | 实测结果 |
|---|---|
| `processes = 6.9` | `passed=True`（截断为 6） |
| `steps = 8.9` | `passed=True`（截断为 8） |
| `processes = "6"` | `passed=True`（字符串被当整数） |
| `summary.parquet` 的 `status = 0.5` | `passed=True`（截断为 0，被当作「非 time-limit」） |
