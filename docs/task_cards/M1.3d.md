## 3. split reader 契约

```python
load_truth_split(
    split: Literal["train", "validation", "test"],
    *,
    canonical_parquet_path,
    canonical_manifest_path,
    split_manifest_path,
) -> pandas.DataFrame
```

- 读取前**逐级验证**：split manifest → canonical manifest → canonical parquet hash；
- 返回**副本**，不得修改 canonical 数据；
- 只接受 `train` / `validation` / `test` 三个精确名称；
- 返回列与 M1.3b canonical 表**完全一致**；
- 时间边界、row index、row count 必须与 manifest **三方一致**；
- 任一 hash / 类型 / 路径 / 时区 / 频率 / 边界 / 行数不一致即 **fail closed**；
- **不接受 bool 冒充整数**；manifest 外部字段**严格校验类型**；
- **不允许**调用者用任意 row range 绕开冻结 split。

## 4. episode / forecast origin 边界门禁（纯函数）

```python
validate_episode_origin(split, origin, horizon_steps)
validate_forecast_origin(split, origin, forecast_cutoff_steps)
```

- `H`、`C` 必须是**严格正整数**：`bool` / `float` / `string` / `0` / 负数一律拒绝；
- 单位明确为 **half-hour steps**；
- episode 最后一个执行点仍须在该 split 内：`origin_index + H <= row_end_exclusive`；
- forecast 可见点 `[origin, origin + C)` 必须完全属于该 split：
  `origin_index + C <= row_end_exclusive`；
- **`H >= C` 时不额外执行 `H + C` 扣除**（双重惩罚是错误的，见 M1.3c §3 勘误）；
- origin 不得位于其他 split；越界**报错，不截断**。

#### 问题 1：split manifest 未被严格验证 —— 只有「生成时写对」，没有「之后不可篡改」

| 篡改 | 改前结果 |
|---|---|
| `year=1999` | **ACCEPTED** |
| `step_minutes=60` | **ACCEPTED** |
| `canonical_parquet_path` 改成别的路径 | **ACCEPTED** |
| `canonical_manifest_path` 改成 `/etc/passwd` | **ACCEPTED** |
| `materializer_revision="nope"`（非法格式） | **ACCEPTED** |
| `no_overlap=false` | **ACCEPTED** |
| `no_gap=false` | **ACCEPTED** |
| `randomized=true` | **ACCEPTED** |
| `leap_day_split="test"` | **ACCEPTED** |
| `episode_origin_rule` / `forecast_origin_rule` 被改写 | **ACCEPTED** |
| `readiness.forecast_ready=true` | **ACCEPTED** |

即：reader 只证明了「当前生成的 manifest 长得对」，**没有**拒绝随后被篡改的冻结声明。
