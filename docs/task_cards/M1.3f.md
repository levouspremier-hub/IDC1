**一、先红反例（至少新增并证明改前失败）**

6. 篡改 `readiness`、`red_lines`、参数块、`max_source_bytes`、`schema`、
   `contract_version` 不得通过；
7. 顶层、source entry、`readiness` 或参数对象**增加未知键**不得通过；
8. 畸形顶层 / list / dict / string / bool / 数字 / null 不得泄漏
   `KeyError`/`TypeError`/`StopIteration`/`AttributeError`；
9. 现有不同 manifest 不得被 `write_manifest_atomic` 覆盖；
10. 相同 manifest 重写必须保持 bytes / hash / `mtime_ns` 不变；
11. 已存在合法 manifest 时重复 `--fetch` 必须**复用** `frozen_at_utc`，
    **不得**因当前时间改变正式 manifest；
12. **结构化人工批准**的 `pv_capacity_kw=500` 应**可通过**；
    缺 `approval` / `decision_id` 或标记 `legacy_inherited` 时必须拒绝
    （修复当前「只要出现 `pv_capacity_kw` 就一律拒绝」的不可延续逻辑）。

**二、严格 manifest 校验（单一入口）**

`validate_public_source_manifest`：顶层键集合精确冻结；所有外部字段先严格验型
（**bool 不得冒充 int**）；`frozen_at_utc` 必须为规范 UTC ISO；
source 数量 / `source_id` 集合与顺序必须精确；每种 `status` 使用精确键集合；
所有固定声明与代码内 `SOURCE_SPECS` **逐字段恒等**；`frozen` 来源再校验本地
bytes/hash/schema/license marker；`blocked`/`refused` 来源**同样校验、不得跳过**；
`readiness` / 红线 / 参数状态完整恒等；任何畸形输入**只抛** `SourcePolicyError`。
`verify_local`、`--verify`、`--fetch` 完成后的复核**共用同一入口**，
不得维护较弱的第二套规则。

**三、冻结不可变性**

正式 manifest 已存在且**语义不同** → fail closed，禁止覆盖；
完全相同 → 直接返回，**不改变 mtime**；重复 `--fetch` 使用现存合法
`frozen_at_utc`；首次生成仍用临时文件 + 原子安装；任一步失败不得破坏已有产物。
