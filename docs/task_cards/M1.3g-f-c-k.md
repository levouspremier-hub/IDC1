## 1. 目标

把**已冻结**的训练配置、M9.2-v3 预登记批次顺序与现有 PPO 闭环接成正式 train-only 入口，
完成**发布验签**后按原规模运行安全 PPO＋联合滚动修正的 **3 个 seed × 512 批**。
本卡只产生正式训练与可审核 checkpoint；**不**声称收敛或性能、**不**运行 validation/test。

### 2.1 与 `train.py` 的关系（实现选择，登记备查）

`train.py` 的 real 路径带一整套结构性守卫（M5.1c 等），且**本卡不需要**改动其 synthetic 语义。
故**不改 `train.py`**：正式入口是**新模块** `safe_rl_v2/formal_train.py`，
由 **Makefile 的 `train` 目标**指向它 ⇒ `make train` 进入正式 train-only 循环、
不落入 synthetic dry run。`train.py` 的既有守卫保持逐字不变。

### 7.3 实测并修复的两处缺陷（如实登记）

1. **`manifest_metadata` 覆盖 writer 保留字段 `seed`**（`c91837b`）：seed 0 于首次长跑中
   **已完成全部 512 批**并在 23:22 写出 `checkpoint_final.pt`，却在收尾 `write_run` 抛
   `ValueError: manifest_metadata 不得覆盖 writer 保留字段：['seed']` ⇒ **训练完成但产物未落盘**。
   改为 `training_seed`（语义不变，仅换名避开保留字段）。
2. **空批次收尾 `IndexError`**（`95555f1`）：从已完成 checkpoint（`next_batch_index=512`）
   恢复时本进程一批都不跑，`records[-1]` 越界。改为从 `optimizer` / `lagrangian` 的
   **活状态**取累计计数。

**中断与恢复证据（保留）**：`runs/m13gfck_seed0_recovered_artifacts/` 是缺陷①发生后
从 `checkpoint_final.pt` 恢复写出的一套产物（该次 invocation `batches_run=0`，
但读到累计 **adam=8192 / lag=512**）。为留下**逐批**证据，seed 0 随后**按原规模重跑**；
两套产物并存，未覆盖历史。
