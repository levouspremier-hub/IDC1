## 1. 三项修正

1. **提交与运行时序**：先提交修正后的代码，再启动新的 train-only 短跑，使 manifest 与
   checkpoint 的 `code_revision` 指向**包含实际运行代码**的提交。现有
   `m13gcj_controlled_*` run 与 checkpoint **保留、不覆盖、不改写**，在卡内标明其 revision
   早于实现提交，仅作**历史诊断证据**。
2. **run 来源账本**：成功 run 的 manifest 写入**非空且可从实际输入重算**的三个 hash：
   依赖 hash = `uv.lock`；数据 hash 复用 `evaluation.sources.canonical_source_digests()` 的
   现有口径；场景 hash 绑定**本次实际使用的 train origin 与 formal injection provenance**。
   冻结配置记录的六项资产 hash 须与 **live 已验签资产**一致（不抄冻结文件里的旧字符串）。
   checkpoint 同样记录可核对的配置、来源与 code revision。
3. **环境种子**：训练环境由**本次 master seed** 加冻结配置的 `seed_offsets.{task,server,forecast}`
   构造，不再以标定脚本固定 `MASTER_SEED=0` 的构造作为训练入口。seed 0 保持原受控语义；
   seed 1 的环境构造种子须实际变为 **1 / 2 / 300001**。把实际使用的三种环境种子、策略采样
   与 minibatch 打乱种子写入 run 证据。显式 RNG 与批次边界恢复语义保持不变。
