## 1. 背景（既有缺陷）

`Makefile` 自 M0.3 起声明：

```make
smoke:
	@test -f scripts/smoke_main_chain.py || { echo "模块未完成：scripts/smoke_main_chain.py 不存在（M4 交付）"; exit 1; }
	@uv run python scripts/smoke_main_chain.py
```

`git log --all -- scripts/smoke_main_chain.py` **为空**——该文件从未存在，
`make smoke` 一直是显式失败。M5.1 阶段验收为此留下一条未通过的门禁。

**本卡补齐脚本，不修改 `Makefile`**（不得靠改声明逃避缺失）。

## 2. 目标

一个**非训练**、可重复执行、带机器可读产物的主链健康检查：
显式种子 → 真实 IDC 环境 → 21 维 raw 动作经**现有** `CorrectorWrapper` → 字段与物理边界检查
→ 写入 `runs/<run_id>/` 五类产物。

## 3. 允许范围（边界）

| 文件 | 动作 |
|---|---|
| `scripts/smoke_main_chain.py` | **新增** |
| `tests/test_m51d_smoke_gate.py` | **新增** |
| `docs/task_cards/M5.1d.md` | **新增**（本卡） |

**不得修改**：`Makefile`、`envs/`、`planning/`、`safe_rl/corrector_wrapper.py`、
`safe_rl_v2/`、`contracts/`、`runs/writer.py`、`marl/`、`grid_model/`、`legacy/`。

## 4. 禁止项

1. **不训练**：不更新任何参数、不实现 PPO、不调用 `optimizer.step()`；
   报告中 `trained` 必须为 `false`，且不得出现任何性能/收敛结论。
2. **不用固定已存在的成功 `run_id` 覆盖旧产物**；同 id 重复写入必须被拒绝。
3. **不修改 `Makefile`** 来绕过缺失。
4. **不放宽任何物理约束**来让检查通过（不得清队列、重置 SOC、跳过任务、抬高接入上限）。
5. **不读取未来真值**。
6. 不使用 `info.get(key, 0)`：环境字段缺失必须报错。

## 5. 脚本要求

1. 显式 `task_seed` / `server_seed` / `forecast_seed` 构造真实 `IDCPriceEnv20D`
   （**既有 env 在任一为 `None` 时使用 `default_rng(None)` 熵源，不可复现**）。
2. 21 维 raw 动作（前 20 维 `[0,1]`，储能维 `[-1,1]`）经现有 `CorrectorWrapper`
   执行 ≥1 步，且**显式**给出 `corrector_time_limit_s`。
3. 逐步检查（每项具名，失败即抛错并写失败 manifest）：
   - raw/exec 维度为 21 且有限、exec 落在动作空间内；
   - 接入上限：`P_grid_kW <= access_limit_kw + tol`；
   - SOC 边界：`bess_soc_min <= bess_soc <= bess_soc_max`；
   - 能量平衡字段存在且有限（`energy_kWh`、`grid_energy_kWh`、`bess_charge_kWh`、
     `bess_discharge_kWh`、`bess_charge_power_kW`、`bess_discharge_power_kW`、`P_IDC_kW`），
     且充放电互斥（不得同为正）。
4. 写入唯一 `runs/<run_id>/`，含 `config.yaml`、`metrics.parquet`、`report.json`、
   `figures/`、`manifest.json`。
5. `manifest.json` 必须写：`revision`、`dependency_lock_hash`（`uv.lock` 的 sha256）、
   `data_hash`、`scenario_hash`、`seed`、`command`、`status`。
   **`data_hash` 的依据必须显式登记**：本 smoke **不使用任何外部数据**
   （M1.2 仍阻塞），故其值为「数据来源记录」的规范化哈希，其原文同时写入 `config.yaml`。
6. 支持 `--base-dir`、`--run-id`、`--seed`（测试用）。
   **默认 `run_id` 每次调用唯一**（时间戳 + 冲突自增），使 `make smoke` 可连续运行
   且永不覆盖既有成功结果；显式 `--run-id` 重复写入必须被拒绝。
7. `report.json` 明确 `trained = false`，只陈述健康检查是否通过。

### 10.6 风险与阻塞

1. `scripts/smoke_main_chain.py` 的 raw 动作由 **seeded numpy RNG** 采样（非策略采样）；
   策略→采集器路径由 M5.1b/M5.1c 的 probe 与测试覆盖。本脚本刻意不依赖 torch。
2. `revision` 取写入时刻的 `git rev-parse HEAD`；工作树存在未提交修改时该值**不**代表
   工作树内容（`write_run` 的既有行为）。本卡未修改 `runs/writer.py`。
3. 本脚本**不训练**，其通过**不**代表任何 PPO 或性能结论。
4. `scripts/` 现在被 mypy 传递扫描（测试导入所致），后续 `scripts/` 改动需保持类型干净。
