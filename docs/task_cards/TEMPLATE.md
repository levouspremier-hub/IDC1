# 任务卡模板

> 使用方式：复制本文件为 `docs/task_cards/Mx.y.md` 并逐字段填写。
> 开工前必须填满 §1.3 五项（**边界、禁止项、验收命令、证据产物、回滚命令**），缺任一项不得开工。
> 依据：`docs/IMPLEMENTATION_PLAN.md` §1.3、`docs/VSCODE_CLAUDE_EXECUTION_PROTOCOL.md` §2.2。

（一句话：本卡交付什么、为何需要。）

（列出允许新增/修改的路径与接口。超出此范围即属「允许范围外修改」，必须在验收记录与最终报告里说明。）

## 3. 禁止项  ← §1.3 必填

（本卡不可改变的语义、红线、不得触碰的目录。例如：不修改 `marl/`、`grid_model/` 主逻辑、`legacy/`、顶层 shim；不放松容量/SOC/充放互斥/任务约束；不清队列、不重置 SOC、不读未来真值。）

## 5. 预期失败

（实现前存在、失败原因明确的命令。例如 `test -f <新文件>` 应失败，或某测试因功能缺失而失败。）

## 6. 验收命令  ← §1.3 必填

```bash
<命令1>   # -> 预期退出码与关键结果
<命令2>   # -> ...
```

（实现后必须转绿；不得为转绿而削弱断言或缩小测试范围。）

## 7. 证据产物  ← §1.3 必填

（测试名 / 机器可读结果 / 运行命令与输出路径，例如 `runs/<id>/metrics.parquet`、`report.json`。）

## 8. 回滚命令  ← §1.3 必填

```bash
git revert <SHA ...>
```

（一张卡一个独立分支提交；失败时 revert 该提交，不带入后续卡。禁止 `reset --hard` / `checkout --` / `git clean`。）
