## 1. 目标

现有 `safe_rl_v2/lagrangian.py` 是 M5.4 阶段的**占位**：

- 约束只有 `budget`，**没有** unit / learning_rate / max_multiplier；
- `update()` 接受**已聚合的标量**，聚合口径没有强制，调用方可以塞任何数；
- `state_dict()` 只存 `budget/estimate/multiplier/log`，**没有版本、单位、约束集合、
  聚合口径、更新序号**，`load_state_dict()` **完全不校验**；
- 乘子没有上限。

本卡重建该模块为**可验证、可恢复**的多约束乘子状态机。
**本卡不把 multiplier 接入 actor loss**（属 M5.3b）。

## 3. 禁止项

1. **不得**把任何 multiplier 接入 actor loss / actor objective（属 M5.3b）。
2. **不得**实现 PPO ratio/clip 或熵项。
3. **不得**让电费（SGD）成为约束或单位；business 必须是 `violation_task_steps`，
   carbon 必须是 `kgCO2e`。
4. **不得**允许标量直接进 `update()`：聚合口径必须固定为**每 transition mean**，
   由模块内部计算，调用方无法绕过。
5. **不得**让 `load_state_dict()` 静默接受旧版本、缺字段、单位不符或约束集合不符的状态。
6. **不得**改动 raw/exec 接线、policy 动作分布、rollout 采集或 models 数学。

## 4. 接口设计

```python
UNIT_VIOLATION_TASK_STEPS = "violation_task_steps"   # business：每 transition 的违规任务·步
UNIT_KG_CO2E = "kgCO2e"                              # carbon：每 transition 的排放质量
AGGREGATION_PER_TRANSITION_MEAN = "per_transition_mean"

REQUIRED_CONSTRAINTS = ("business", "carbon")
REQUIRED_UNITS = {"business": UNIT_VIOLATION_TASK_STEPS, "carbon": UNIT_KG_CO2E}

@dataclass(frozen=True)
class ConstraintSpec:
    name: str
    budget: float
    unit: str
    learning_rate: float
    max_multiplier: float

@dataclass
class ConstraintState:
    name, budget, unit, learning_rate, max_multiplier,
    estimate, multiplier, updates, log      # log: 每次更新后的乘子

class Lagrangian:
    def __init__(self, specs: Sequence[ConstraintSpec], *,
                 aggregation: str = AGGREGATION_PER_TRANSITION_MEAN) -> None
    def update(self, batch_signals: Mapping[str, Sequence[float]]) -> dict[str, float]
    def multipliers(self) -> dict[str, float]
    def state_dict(self) -> dict
    def load_state_dict(self, state: dict) -> None
```

### 4.1 更新规则

```
estimate[name]   = mean(batch_signals[name])          # 每 transition mean（模块内计算）
multiplier[name] = clip(multiplier[name] + lr * (estimate - budget), 0.0, max_multiplier)
updates[name]   += 1 ; log[name].append(multiplier[name])
```

逐约束**完全独立**：`business` 的更新不得读/写 `carbon` 的任何量。

### 4.2 `state_dict()` 形态

```python
{
  "contract_version": CONTRACT_VERSION,        # contract-v7
  "aggregation": "per_transition_mean",
  "updates": int,                              # 全局更新序号
  "constraints": {
      "business": {name, budget, unit, learning_rate, max_multiplier,
                   estimate, multiplier, updates, log},
      "carbon":   {...},
  },
}
```

### 4.3 `load_state_dict()` 必须显式拒绝

| 情形 | 报错 |
|---|---|
| 非 dict / 缺 `contract_version` | `TypeError` / `ValueError` |
| 版本不是 `CONTRACT_VERSION`（含旧 v6、无版本） | `ValueError` |
| 缺 `aggregation` / `updates` / `constraints` | `ValueError` |
| `aggregation` 不符 | `ValueError` |
| 约束集合 ≠ `REQUIRED_CONSTRAINTS` | `ValueError` |
| 条目缺任意字段 | `ValueError` |
| `unit` / `budget` / `learning_rate` / `max_multiplier` 与当前 spec 不符 | `ValueError` |
| `multiplier` 非有限、为负、超 `max_multiplier` | `ValueError` |
| `log` 非列表 / 含非有限数 / 长度与 `updates` 不符 | `ValueError` |

## 5. 版本升迁

`CONTRACT_VERSION_ID`：`contract-v6` → **`contract-v7`**。

理由：`state_dict()` 的字段集、单位、聚合口径与更新序号都是**新增的可恢复状态 schema**，
旧 v6 状态缺少它们，静默接受会让恢复出的乘子与单位对不上。

**须如实登记的下游影响**：`CONTRACT_VERSION_ID` 是本仓库唯一版本源，
提升它同时会把 `RolloutBuffer` payload 与 `checkpointing` 的版本改为 `contract-v7`，
即**旧 v6 rollout buffer 与旧 v6 checkpoint 也会被拒绝**。这是该设计（单一版本源）
的必然结果，本卡接受并在 §10 风险中登记。

| 断言 | 证据 |

### 10.5 演化与恢复证据

- **纯函数性**：`test_evolution_is_a_pure_function_of_state_and_batches` —— 同一初始状态 +
  同一批次序列 → `state_dict()` 逐位相同。
- **中断恢复**：`test_recovery_then_continue_matches_uninterrupted_run` —— 中途落盘、
  恢复到新实例、继续剩余批次，最终状态与不中断演化**逐位相同**。
- **可序列化**：`test_state_dict_is_json_serializable`。
- **边界**：`test_load_accepts_multiplier_exactly_at_bounds`（乘子恰为 `0` 或
  `max_multiplier` 是合法状态）。

### 10.7 风险与阻塞

1. **版本源是全局的，连带影响必须知情**：`CONTRACT_VERSION_ID` 提升到 `contract-v7`

   该文件）。纯文档不一致，不影响行为；待后续卡修正。
