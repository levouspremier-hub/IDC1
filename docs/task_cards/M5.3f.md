## 1. 缺陷（M5.3e 遗留）

M5.3e 让 `Lagrangian.update()` 拒绝非法信号，但**校验的位置太晚**：
`dry_run_update` 在调用 `update()` 之前已经跑完了

```
policy.forward(obs) → policy.forward(next_obs)          # critic 前向
compute_three_value_targets(...)                        # 三套 target
policy.evaluate_raw_actions(...) + policy.forward(obs)  # actor
loss.backward()                                         # 反向
optimizer.step()                                        # 参数更新  ← 已经改了策略
```

才轮到 `lagrangian.update(...)` 报错。此时：

- **策略参数已被更新**（`optimizer.step()` 已执行）；
- **optimizer 状态已被推进**（Adam 的动量/步数）；
- 只有乘子状态是干净的。

也就是说：一次含非法约束信号的 rollout 会**部分地**污染训练状态 ——
恰恰是最难排查的那种半完成状态。正确的行为是**在任何副作用之前**失败。

## 4. 实现要求

1. 在**任何** `forward` / `backward` / `optimizer.step` **之前**，对从 `RolloutBuffer`
   提取的 `business` / `carbon` 序列做**纯预检**（不接触任何状态）。
2. 预检失败（负值、非有限值、空序列、约束集合不符）时：
   - `optimizer.step` **不得**被调用；
   - policy 参数**逐位不变**；
   - optimizer state **不变**；
   - Lagrangian state **不变**；
   - 异常必须指出**具体约束与失败原因**。
3. 正常路径顺序固定为：
   `preflight → loss/backward → optimizer.step → lagrangian.update`。
4. 预检与 `update()` 共用 `validate_constraint_signals`（M5.3e），不得各写一套。
5. 修正 `train.py` 顶部过时表述：M5.3 已完成乘子目标接线
   （`A_reward − λ_b·A_business − λ_c·A_carbon`）；
   **M5.4 尚未完成**的是训练入口、泄漏门禁与 corrector 开/关可复现性。
