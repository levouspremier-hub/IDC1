## 1. 目标

把冻结配置接成一条**真实训练闭环**，并在**批次边界**做版本化训练恢复 checkpoint：

```text
configs/training/idc_training_config_v1.json
  → policy / Adam / 两个 Lagrangian 乘子 / corrector on 0.25 s / CPU 单线程
  → 一批 = 4 个 train episode × 48 步 = 192 transitions
  → 4 epoch × 每 epoch 4 个 48-transition minibatch = 16 次 Adam step
  → 整批 192 条信号各更新一次 Lagrangian
  → 批次边界保存可恢复 checkpoint（下一批游标 + origin 列表）
```

## 3. 禁止项

- 超参数**只**取冻结配置，不从 probe 示例另选；不在训练引擎内部暗定**长期** origin 抽样
  规则（长期安排留给 M9.2 冻结）。
- `old_raw_log_prob`、三头 advantage、critic target 必须在**该批首次更新前**算好并在
  4 个 epoch 内**固定**；新 log-prob **始终**由 `raw_action` 现算；`exec_action` 只用于
  环境执行与审计。
- 两个 Lagrangian 乘子**每批各更新一次**（用整批 192 条信号），**不得**按 minibatch 更新。
- 受控短跑 checkpoint **不得**标成已完成正式训练的评估输入；`training_scope` 必须是
  `controlled_short_run`；不得宣称性能 / 收敛 / 正式训练完成。
- 失败也写失败 run，**不覆盖**既有成功 run。

### 7.2 训练闭环语义（实测）

```text
一批 = 4 episode × 48 步 = 192 transitions
     → 4 epoch × 4 minibatch(48) = **16 次 Adam step**
     → 整批 192 条信号各更新**一次** Lagrangian
连续 3 批的累计计数实测：Adam **16 / 32 / 48**，Lagrangian **1 / 2 / 3**
```

超参数**全部**取自 `configs/training/idc_training_config_v1.json`（corrector on / 0.25 s、
CPU 单线程、`gamma_per_step=sqrt(0.99)`、`gae_lambda=0.95`、`clip_epsilon=0.2`、
Adam `lr=3e-4`、乘子 lr/上限来自 `training.multipliers`）；入口**不提供**任何覆盖开关。
`advantage` / critic target 在该批首次更新前一次性算好并固定；新 log-prob 始终由
`raw_action` 现算；`exec_action` 只用于环境执行与审计（`raw_exec_difference_count=192/192`）。

### 7.3 **实现中实测并修复的真实缺陷（重要）**

首轮 A/B/C 三条轨迹**互相不一致**（A 批 0 摘要 `a766d2f0…` vs B `3573865f…`）。
隔离实验（同一命令跑两次，`corrector off`）显示 raw 动作摘要也不同
⇒ **不是** corrector 的 0.25 s 墙钟预算所致，而是**策略初值消耗了全局 Torch RNG**
（`nn.Linear` 默认初始化），两个进程因此得到不同初始权重。

修复：新增 `build_seeded_policy`，在 `torch.random.fork_rng(devices=[])` 区间内以显式
`seed` 播种后构造，退出即还原全局 RNG（实测：调用方全局 RNG 状态逐位不变）。
修复后两次同命令短跑的批次摘要与策略摘要**逐位相同**
（`5137bc01ab1acc06…` / `3564009e3951ca7b…`）。

修复前的三条 run 未作为任何交付证据，已改名为
`runs/m13gcj_superseded_pre_seed_fix_{3batch,2batch,resume_b3}/` **保留**（未删除）。

## 8. 人工复审结论（2026-09-28）

**部分通过：PPO 闭环与批次恢复对照有效；来源账本与环境种子接线未达交付要求。**

**有效（予以确认）**：

- 一批的语义（192 transition → 4 epoch × 4 minibatch = 16 次 Adam step → 整批信号
  更新一次乘子）与累计计数 **Adam 16/32/48、Lagrangian 1/2/3** 实测无误；
- 第 3 批「连续 vs 新对象恢复」的对照摘要一致，且**边界对照点在第 3 批开始前**
  （Adam 32 / Lag 2），不是「同一最终状态」的伪证；
- 训练恢复格式与 `checkpointing/eval_input.py` 的角色区分成立；
- §7.3 记录并修复的「策略初值消耗全局 Torch RNG」是真实缺陷，修复可复现。

**未通过（须返修）**：

1. **提交与运行时序**：现有三条 run 的 `manifest.revision = f255e9b`（任务卡提交），
   而该 revision **不含** `safe_rl_v2/formal_train_loop.py`（实测 `git ls-tree` 计数为 0，
   该文件由 `5c898e4` 引入）⇒ manifest 的 `code_revision` 指向的提交**不含实际运行代码**。
2. **来源账本缺失**：三条 run 的 `dependency_lock_hash` / `data_hash` / `scenario_hash`
   **实测全为 `None`**（见 §7 的证据产物要求与仓库 run 规范）。
3. **环境种子接线**：训练环境仍经 `scripts.calibrate_training_config.build_env_for_origin`
   构造，其 `MASTER_SEED` 固定为 0、不随本次 master seed 变化 ⇒ 换 seed **不会**改变
   环境构造种子，与「由本次 master seed 加冻结配置 seed_offsets 构造」不符。

**返修卡：M1.3g-f-c-j-R1。** 现有三条 `m13gcj_controlled_*` run 与 checkpoint
