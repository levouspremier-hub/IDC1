## 3. 验收

先提交失败测试，证明基线在 manifest 已存在时仍可能进入复制或天气下载路径。实现后：

1. 已有 manifest 时，`--usep-zip`、`--generation-zip`、`--sasea-zip`、`--fetch-weather`
   任一出现都在复制、下载、核验之前失败。
2. 已有 manifest 的 `--verify` 与同内容 `--write-manifest` 为纯只读路径。
3. manifest 缺失时保留首次冻结：获取/复制、完整核验、显式 `--write-manifest` 创建。
4. 四个真实 raw 与 manifest SHA-256 在失败前后不变。

运行专项 pytest、真实本机只读 `--verify`、同内容 `--verify --write-manifest`、
`make check`、`git diff --check`，结束时工作树为空。

## 4. 证据与回滚

- 测试会 mock 写入函数，证明被拒绝时 `_copy_input` 和 `fetch_open_meteo_weather` 均未调用。
- 记录四份 raw 及 manifest 的 SHA-256 前后值；原始文件永不纳入提交。
- 本卡提交可按反序 `git revert`，不改动 M1.2a/b 历史提交。
