## 1. 目标

使所有由 MIP / raw-projection 触发的 base-shortage 诊断也受**同一全局 deadline** 约束；
任何诊断阶段 timeout 都必须安全返回 **timeout**，**不能在主求解已到 deadline 后继续求解**。

## 2. 边界（允许修改的文件）

- `planning/model.py`
- `tests/test_m43a1_base_shortage_diagnostic.py`、`tests/test_m43b_time_indexed_mip.py`、`tests/test_m44a_raw_projection.py`
- 新增 `docs/task_cards/M4.4a2.md`（本任务卡）

## 3. 禁止事项

- 不修改 `envs/`、corrector wrapper、`contracts/`、`safe_rl` PPO/buffer、`marl/`、`grid_model/`、`legacy/`；
- 不修改物理约束、投影目标、动作映射或业务 slack 语义；
- 不删除 legacy `solver.py` / `build_milp`；
- **不以「诊断未完成」伪造 `base_shortage` 或可执行动作**。

## 4. 实现要求

1. `diagnose_base_feasibility()` 与其内部**正常 base-only LP、shortfall LP 都必须接受共享 deadline 或剩余 `time_limit`**；
   **两次诊断 LP 不得各自重新获得完整预算**。
2. 对 `solve_time_indexed_mip()` 与 `solve_time_indexed_mip_raw_projection()`：
   - 主 MIP 返回 `infeasible` 后，诊断**只能使用主求解后的剩余预算**；
   - 剩余预算 `<= 0` → **不启动诊断**，直接 `timeout`；
   - 诊断自身 timeout → **整体结果 `timeout`**，**不得误报 `base_shortage`**；
   - 只有诊断**在预算内完成且证明 base-only 不可行**时，才返回 `base_shortage`；
   - 诊断证明 base-only **可行**但主模型 infeasible → 返回 `solver_failure`；
   - timeout 路径**不得使用 incumbent、不得产生执行动作**。
3. **结构审计保留**：timeout/failure 仍输出 `backend`、`H`、变量数、整数变量数、主阶段与诊断阶段状态、每阶段耗时；
   明确记录「**诊断未启动**」或「**诊断 timeout**」。
4. 更正 `planning/model.py` 顶部现行注释：`planning/corrector.py` **已于 M4.4a 切换到 H 步 MIP，不再使用旧 `build_milp`**；
   仅 `planning/solver.py` 与旧测试仍保留 legacy 路径。**不得改写历史任务卡。**
