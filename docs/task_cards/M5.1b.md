## 1. 目标

把「策略采样 → 环境（可选修正器）→ mock-free 的 transition」这条链**真实接通**，
使 `RolloutBuffer` 成为后续 PPO 的唯一样本来源。

**只做有界 raw 动作采样与真实 rollout 收集。** 本卡**不实现** PPO ratio/clip、
GAE、actor loss、熵正则、拉格朗日乘子更新、checkpoint 或训练循环。

## 2. 分支说明

M5.1a 与 M5.1b 是同一条 M5 阶段契约链的前后两半（v6 schema → 真实采集），
共用分支 `p4-safeppo-m51a-rollout-contract`；不为 M5.1b 另建分支，
以便 M5.1 阶段验收在单一 HEAD 上完成。M5.1a 的提交保持独立可 revert。

## 4. 禁止项

1. **不得**实现 PPO ratio/clip、GAE、advantage、actor loss、熵项或乘子更新；
   **不得**调用 `optimizer.step()`；本卡产物**不得**被描述为「已训练」或「性能有效」。
2. **不得**用 `clip` 修改采样动作后仍保存原 log-prob：`old_raw_log_prob` 必须对应
   最终落库的 `raw_action`。
3. **不得**用 `info.get(key, 0)` 或任何默认值伪造缺失的环境信息字段；缺字段必须报错。
4. **不得**让 `exec_action` 影响或覆盖 `raw_action` / `old_raw_log_prob`。
5. **不得**为保证「可行」而清队列、重置 SOC、跳过任务或放宽接入/SOC/互斥约束。
6. **不得**读取未来真值；采集只用当前观测。
7. **不得**在 corrector 开启时给出隐式 `corrector_time_limit_s`。

## 5. 接口约定

### 5.1 `SafePPOPolicy`

```python
act(obs) -> (raw_action, old_raw_log_prob, values)
```
- `raw_action`：**有界**，前 `action_dim-1` 维 ∈ [0,1]，末维 ∈ [-1,1]；
- `old_raw_log_prob`：**最终 raw_action** 的对数密度（含 tanh-squash 的 Jacobian 修正）；
- 签名与三元组结构对 M5.4 保持不变。

```python
evaluate_raw_actions(obs, raw_action) -> log_prob
```
对给定 raw 样本重算 log-prob，必须复现 `act()` 对**同一样本**的值。

### 5.2 `safe_rl_v2.rollout.collect_rollout`

```python
collect_rollout(env, policy, buffer, *, steps, seed=0,
                corrector_on=False, corrector_time_limit_s=None) -> dict
```
- `corrector_on=True`：raw 动作**原样**送入 `CorrectorWrapper`；且 `corrector_time_limit_s`
  必须显式给出，否则报错；
- `corrector_on=False`：raw 动作**原样**送入基础 env；
- 每条 transition 完整写入 `raw_action`、`old_raw_log_prob`、`exec_action`、
  `next_observation`、`terminated`、`truncated`、具名业务违规量、具名碳排放量、
  具名电费与 JSON 安全 `correction_info`。

### 10.5 风险与阻塞

1. **`IDCPriceEnv20D` 默认不可复现**：`task_seed`/`server_seed`/`forecast_seed`
   任一为 `None` 时使用 `np.random.default_rng(None)` 熵源，跨实例/跨进程结果不同。
   本卡**未修改 env**，改为在使用侧（测试与 probe）显式给出三类种子。
   **M5.2 及以后的训练入口必须沿用同一约束，否则无法复现。**
2. `safe_rl_v2/train.py::_clip_action` 仍存在（M5.4 既有代码）。由于 `act()` 现已返回
   有界动作，该 clip 对落在 [0,1]/[-1,1] 内的值恒为恒等映射，**不再构成「clip 后沿用旧
   log-prob」**；但该冗余调用应在 M5.2/M5.4 接线时清理。本卡不改 train.py。
3. 修正器开启时每步约 20 ms（预算 0.05 s），大批量采集的吞吐属 **M9.1** 范畴，本卡不测量。
4. **本卡不实现** PPO ratio/clip、GAE、actor loss、乘子更新、checkpoint 与训练循环（M5.2–M5.5）。
