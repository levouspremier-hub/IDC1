## 3. 改前可复现缺陷（三项，均为冻结历史产物上的实测）

### 3.1 `summary.parquet` 字段名错误

```text
$ uv run python -c "import pandas as pd; print(sorted(pd.read_parquet('runs/m54h1_matrix/m54h1_hogs4/summary.parquet').columns))"
['budget_s', 'corrector_failure', 'corrector_reason', 'digest', 'elapsed_s', 'message',
 'mip_dual_bound', 'mip_gap', 'mip_node_count', 'node_cap', 'node_cap_injected',
 'options_json', 'pid', 'remaining_deadline_s', 'skip_reason', 'skipped', 'stage',
 'status', 'step', 'success', 'unavailable_fields', 'wall_clock_disabled_in_probe']
→ has options: False | has options_json: True
```

约定字段名是 `options`（规范 JSON 字符串）。当前只有 `options_json`，且编码规则未固定。

### 3.2 `overall` 与 `release_gate` 自相矛盾

```text
$ uv run python -c "import json; r=json.load(open('runs/m54h1_matrix/m54h1_hogs4/report.json')); print(r['release_gate']['blocked'], r['overall'])"
True {'blocked': False, 'blocked_modes': [], 'conclusion': 'wall_clock_budget_dominant', ...}
```

同一 report 内 `release_gate.blocked=true` 而 `overall.blocked=false`。
根因（`scripts/probe_corrector_repro.py` 旧 `main`）：有矩阵时

```python
overall = {"blocked": attribution["conclusion"] != "wall_clock_budget_dominant", ...}
```

即 **`overall` 由 `attribution` 推导** —— 归因成立被误当成阶段已放行。
同时 `summary.json` 的顶层 `conclusion` 也写成 `wall_clock_budget_dominant`，
与 `manifest.status="failed"` 冲突：下游会读成「已放行」。

### 3.3 未绑定 node cap 被写成 candidate

```text
$ uv run python -c "..."
runs/m54h1_matrix/m54h1_nodealt: mip_node_count unique: [1.]   node_cap_injected unique: [100 10000]
candidate_notes.node_cap_alternative_semantics = {"caps_tested": ["100","10000"],
  "stable_caps": ["100","10000"], "candidate": true, "note": "替代语义臂（移除 time_limit）稳定 -> 可作为候选"}
```

测试 cap 为 100/10000，所有可行解 `mip_node_count=1`，cap **从未绑定**。
替代语义臂稳定是因为**移除了 `time_limit`**，不是因为 node cap 生效。
`candidate=true` 属名不副实，属 M5.4h1 的失效结论。

## 5. 最小实现要求

- 只修改 probe/ledger/report 逻辑；**不改变** corrector 求解结果、rollout action、`time_limit`。
- `summary.parquet` 写 `options`（规范 JSON：`json.dumps(value, sort_keys=True,
  separators=(",", ":"), ensure_ascii=False)`）；**不得**同时保留 `options_json` 兼容列；
  **未执行的 skipped 阶段允许 `options=null`**。
- 语义分层，固定为：
  - `release_gate`：决定 M5.4 阶段是否放行；
  - `overall`：**只**反映 `release_gate` 的最终阶段状态；
  - `attribution`：只解释不稳定的原因，**绝不**决定是否放行。

  至少保证 `report["overall"]["blocked"] == report["release_gate"]["blocked"]`；
  release gate blocked 时：`overall.blocked=true`、`overall.conclusion="blocked"`、
  `manifest.status="failed"`、退出码非 0、`summary.json` 的阶段状态与 report/manifest 一致。
  即使 `attribution.conclusion="wall_clock_budget_dominant"` 也不得把 `overall` 或 `manifest` 写成成功。
- `candidate_notes` 必须提供机器可读字段 `node_cap_effective` 与 `node_cap_candidate`，
  未绑定时均为 `false`，并记录原因：观测到的 `mip_node_count` 未触及 cap；
  稳定性只能归因于 probe 中关闭 wall-clock；不得把 `mip_max_nodes` 描述为生产候选或确定性根因。
  0.25 s 仍只能称为 machine-local wall-clock candidate。
- 保留逐 `step × Stage A/B` **恰好两行**的审计语义；skipped 行测量字段继续为 `null`，不得填零。
- **不得回退** M5.4h1 的 load/provenance 真实性修复。
