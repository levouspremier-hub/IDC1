## 4. deadline 语义

`time_limit_s` 是**一次 raw-projection 调用的总预算**，不是阶段 A/B 各自的预算。

- 使用 **monotonic deadline**：`deadline = now + time_limit_s`；
- 阶段 A 使用**总剩余预算**；
- 阶段 A 成功后，阶段 B 只能得到 `deadline − now`；
- **若阶段 A 后预算已耗尽，不启动阶段 B，直接返回 `timeout`**；
- 两阶段 MIP 实际收到的 `options.time_limit` 必须反映上述剩余预算。

## 5. 阶段 B 失败分类（保真）

| 阶段 B 结果 | 分类 |
|---|---|
| `time_limit` | `FAILURE_TIMEOUT` / `solver_status="time_limit"` |
| solver error | `FAILURE_SOLVER_FAILURE` |

**不得把 stage-B timeout 改写为 `solver_failure`**；timeout 路径**不得**调用 `diagnose_base_feasibility`。

## 6. 活链路不得无界调用

- `planning.corrector.correct()` 必须**显式接收并校验正数时间预算**（非正数抛 `ValueError`）；
- `CorrectorWrapper` 构造时必须**显式接收 `corrector_time_limit_s`** 并传入 corrector；
- **不得以任意隐式默认值掩盖运行时预算决策**；本仓库所有 wrapper 创建点、测试与 `planning.probe` 均显式传值；
- probe 中该值必须标记为**测量参数**，**不是研究结论或生产默认值**。

## 7. 失败结果仍须保留结构审计信息

timeout/failure 时 `RawProjectionResult` 仍须保留：`backend="mip"`、`H`、`n_variables`、
`n_integer_variables=H`、阶段 A/B 状态与耗时。**不得用全 0 元数据掩盖实际求解规模。**

## 9. 性能事实（本机实测，如实记录）

在本机（Apple M5 / macOS 26.6.2 / CPU 后端）实测**未限时**的单次 `wrapper.step`：

| 测量 | 均值 | 中位 | P95 | 最大 |
|---|---|---|---|---|
| `wrapper.step`（3 轮 × 24 步） | 0.0265–0.0295 s | 0.0255–0.0317 s | 0.0462–0.0547 s | 0.0553–0.0586 s |
| `correct()` 单独（20 次，同快照） | 0.0131 s | — | 0.0133 s | 0.0177 s |
| 两阶段内部（A / B） | A≈0.0026 s / B≈0.0042 s | | | |

> **与卡片所述「约 0.20 秒/步、P95 约 0.29 秒/步」不一致**：本机复现不到该量级（实测约低 7 倍）。
> 差异可能来自机器/环境配置或测量口径（例如是否含首次编译、是否含 `env.step` 之外的开销）。
> 本卡**如实记录本机实测值**，并标注该差异，不以任一方数字作为结论。

**本卡只保证安全 deadline 语义，不宣称已达训练吞吐目标**；后续 **M4.6** 必须依据 benchmark
决定优化策略与可接受预算。
