## 1. 目标

消除 `scenario/scenario.py` 与 `contracts.ScenarioBundle` 的重复定义，使所有新主链场景提供、snapshot 与验证都使用**唯一**的 `contracts.ScenarioBundle`（contract-v2）。

## 2. 已发现的问题（改造前）

| 问题 | 现状 |
|---|---|
| 重复类型 | `scenario/scenario.py:26` 自定义 `@dataclass(frozen=True) class ScenarioBundle`，与 `contracts/models.py` 的冻结契约**同名不同型** |
| 字段分叉 | 本地类有 `current`/`forecast`/`hash`，契约类有 6 个具名预测字段 + `UNITS` + `source_hashes`；本地类**缺 `carbon_forecast`** |
| 验证不覆盖 | `contracts.validators.validate_scenario` 只对契约类型生效，场景提供器输出绕过了它 |

## 3. 边界（允许修改的文件）

- `scenario/scenario.py`（删除本地类，构造契约类型）
- 该模块的直接消费者：`scenario/__init__.py`、`tests/test_scenario.py`
- 新增 `tests/test_m13a_canonical_bundle.py`
- 新增 `docs/task_cards/M1.3a.md`（本任务卡）

## 4. 禁止项

- 不下载、伪造或补写 M1.2 全年真实数据；
- 不另建第二个 `ScenarioBundle`；不改 `contracts/`（因此**不改 contract-v2 形状、不升级版本**）；
- 不改 `marl/`、`grid_model/`、`legacy/`、物理链、动作空间、训练代码。

## 5. 六类预测字段（契约要求）

`price` / `load` / `pv` / `wind` / `temperature` / `carbon`，各自长度 == `forecast_cutoff`，并带 `source_hashes`、`synthetic`、`split`、`start`、`horizon`、`forecast_cutoff`。

## 6. 数据边界（不变）

M1.2 状态保持 **「数据组合未验证 / 正式数据接线阻塞」**：当前只允许生成**显式 `synthetic=True`** 的开发/测试场景；正式模式（`synthetic=False`）在无 manifest 时抛错，绝不把合成场景标为真实数据。
