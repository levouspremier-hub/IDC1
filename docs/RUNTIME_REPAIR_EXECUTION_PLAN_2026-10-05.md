# IDC 问题修复与主机提速执行方案

配套 [项目交接](CHATGPT_HANDOFF_RUNTIME_REPAIR_2026-10-05.md)。
本方案承接用户批准的三档预算、三种子短训、4h 验收、先 seed0 后 seed1/2，
并加入最新要求：将单 seed 预计约 7.5 小时作为必须调查和优化的效率问题。
本文件是执行计划，不是已经获得训练资格的报告。

## 1. 总顺序与完成定义

**核对现有修复 → 完成候选发布与诊断接线 → 主机分项计时 → 有证据的等价提速 →
固定最终代码 → 主机完整门禁 → 预算/短训/4h资格 → 冻结新发布 → 新初始化长训。**

性能开发应放在最终 4h 验收之前；验收后又改执行路径，不能直接沿用旧资格。
“提高预算”和“提速”是两件事：限时是上限，不代表每步必用满；增预算可能减少失败，
也可能延长耗时。最终同时报告可靠性、A 降级比例、经济表现和速度。

问题完成标准：
- 故障处理：合格 A 能保留，无合格方案不会以零动作继续污染训练。
- 恢复与审计：失败现场和批前状态可读取，日期、种子、RNG、更新计数不跳变。
- 运行资格：固定主机/代码/配置下，预登记诊断、短训、完整 4h 均通过。
- 效率：找到主瓶颈，交付经测量的优化前后对照和新的 512 批时间估计。
  用户未指定硬性小时上限，不擅自把“低于 4 小时”等设为已承诺验收线。
  若没有可靠收益，明确效率问题未解决及剩余瓶颈，不以减少工作量交差。
- 实验有效性：不使用 validation/test，不让历史资格或旧权重跨新语义恢复。

## 2. 卡 A：补齐发布、诊断和停止机制验收

开卡前：核对 Git/status/diff、读仓库规则、登记边界/禁止项/命令/证据/回滚 SHA。
先审查已提交修复，避免重写。现有 121 项测试是起点，不是主机完整门禁。

### 2.1 发布与入口（当前实际阻塞点）

1. 为修复后的执行语义创建独立版本和候选配置路径，旧 r5/r7 原样保留。
   注册预算候选仅 .25、.50、1.00；其余奖励、业务/碳预算、网络、优化器、日期不变。
2. 将“候选可诊断/可短训”与“正式训练放行”分开，避免必须先有正式发布才能做资格实验。
   候选同样必须校验完整代码闭包、依赖锁、数据/场景和配置摘要，不能跳过验签。
3. 旧标定中仍适用的尺度和预算必须明确继承来源；旧实测 .25 不能冒充 .50/1.00 已标定。
   新候选只改变已登记的求解执行语义/预算；用新资格证据负责放行。
4. 更新 `inventory_train`、诊断、发布验证、resume/eval-input 的一致绑定。
   原 `load_config` 仍强制 .25，原 seed0 gate 继承 r6/r7：必须替换为新版资格验证，
   不得简单放开常数或照搬旧 gate。新版 checkpoint 拒绝旧训练状态。
5. 旧 final 只通过专用 train-only 诊断入口加载：核对既定 SHA、21/523 维、schema 和角色；
   只加载策略，不恢复优化器/乘子，不把诊断兼容写进正式恢复路径。
6. 资格报告绑定候选语义摘要；发布后复核执行字节/配置与资格完全一致。
   若只新增签名元数据，明确核验等价范围；执行源发生变化则资格不自动继承。

### 2.2 故障与恢复闭环

以现有 focused tests 为基础，只补真实缺口：
- A 最优+B 超时/无预算：完整检查合格才执行 A；正常 B 保持既有目标和偏移约束。
- A 非最优/无方案、B 求解错误、不合格候选：拒绝执行，本批采集失败不增加更新数。
- 原始动作/log-prob 保留；失败现场含来源、实际阶段状态、候选检查、预算和耗时。
- 非有限 loss/gradient 在相应 Adam 前阻断；若已有部分 minibatch 更新，真实记录次数，
  使用批前 checkpoint 恢复，不能把部分更新说成 0。
- 物理违规停止；普通业务惩罚如实记录，不因成本不好或业务信号高而删样本。
- 真实小规模批次边界恢复验证：初始批、已有成功批后失败各至少覆盖实际相关路径，
  保存 RNG/Adam/乘子/日期游标，显式恢复到新 run ID。没有自动跳过或无限重试。
- 模拟超时验证代码分支；历史真实快照验证真实行为，分开记录证据。

默认不改 `env.step`；若确有必要，严格先提交该卡失败测试再改。

## 3. 卡 B：主机性能诊断与等价优化

### 3.1 建立修复后基线

旧 7.549 小时估计仅作背景。使用已修复语义、固定主机与新版本重测。
主机上完整测试、profiling、正式计时互不并发；Mac 不承担这类长任务。
先用预登记小样本拆分开销，无资格前不启动 512 批；失败样本保存并停止对应训练任务。

分别记录：
- job 排队、worktree/环境准备、输入拷贝、训练入口启动与最终验签、回传时间。
- env 构建：来源/文件 hash、fingerprint、cache 命中、场景注入、环境初始化。
- rollout：策略推理、快照/服务预留、规划矩阵构建、可达性检查、A、B、候选检查、环境 step。
- PPO：优势/target、前后向、Adam、乘子；checkpoint 序列化、写盘与读回、journal。
- 墙钟/CPU、冷启动/稳态、每步每批均值及 P50/P95/max、内存，预算耗尽/降级状态。

注明计时嵌套关系，不重复求和；残差只能称残差，不能假称独立计时。
详细 profiler 只用于独立诊断，不把带明显插桩开销的耗时当最终资格速度。
先看现有 timer 和轻量分项，证据不足才扩大 profiling。

### 3.2 优先级与实现候选

**优先一：环境构建约 29% 的开销。**
检查现有 `_verified_train_input` 缓存为何仍每批约 15 秒：是缺失命中、不同日期、
fingerprint 全量扫描，还是注入/构造占用。根据实测选择修复，不假定已有缓存无效。
允许在经过验证的不可变输入范围内复用静态数据、模板和解析结果；缓存 key 必须覆盖
代码/数据/配置、origin、horizon、可见窗口及必要种子。修改输入必须失效或明确拒绝。
队列、SOC、RNG、已推进的环境实例等可变状态不得跨回合共享。
不得以关闭 provenance/hash 校验提速；若改为 job 初始化验签、进程内不可变复用，
须同时实现并验证该不可变边界，不允许仅靠“文件大概不会变”。

**优先二：rollout 约 71% 内部的实际瓶颈。**
先分开模型构建与求解，再考虑复用稀疏结构/索引、减少重复分配和转换、
复用真正不变的系数。SOC、任务期限、预测窗口、接入容量、终点目标等动态量每步正确更新。
A/B 共用原全局预算，不给 B 额外补时。完整候选检查不能为提速删去。
增量建模或求解器持久实例只有在后端确实支持且可验证重置语义时才考虑；
不把更换求解器、warm start 或启用多线程当作天然等价，要单独登记版本、数值与结果核对。
先做低风险热点优化，不为了实现它们贸然重构全套算法。

**优先三：写盘与平台。**
旧实测写盘残差很小，不预判它是主瓶颈；新增批前/16批 checkpoint 后重新实测。
不降低保存频率或取消读回。确认代码、venv、工作数据位于 WSL Linux 文件系统，
测量实际磁盘/内存/CPU状况；不擅自关闭安全软件或修改系统保护设置。
继续单个重型 job、冻结线程设置，不先并行多个 seed 或异步采样改变训练序列。
GPU 暂不作为首选：旧 PPO 更新不足 1%，先解决有证据的热点。

### 3.3 性能验收

- 修复基线与优化版本使用同一主机、依赖、预算、train 日期顺序、模式/随机种子和工作量。
- 分两层比较：同一历史快照输入看计算开销；同一训练协议看端到端吞吐与质量。
  端到端若执行动作变化，后续状态自然变化，不能宣称所有后续逐步输入完全相同。
- 函数/物理量不要求跨机器逐位相同，但必须满足既定容差与约束；缓存复用必须通过
  未缓存对照、失效检查和不可变状态隔离。不给数值误差另开宽容差。
- 限时求解中加速可能改变是否赶上 B，报告 A/B比例和经济变化，不能仅称纯计时收益。
- 输出修复基线/优化版的每批耗时、加速比、吞吐、质量、512批外推及估算限制。
  分开冷启动、稳定期、保存、回传；不要把 7 小时数字简单除以 GPU 倍率。
- 如果无实际收益或代价过大，保留结果并报告可选进一步改动。不能宣称效率问题已解决。

## 4. 卡 C：固定最终代码后的主机资格验收

完成候选实现与性能优化后，提交/推送完整 SHA。主机独立 worktree、锁定依赖和资产。
先运行相关测试及完整 `make check`，结束后才启动计时资格实验。
若代码变更使资产绑定失效，按依赖闭包验证/刷新新版本，不修改历史记录伪造通过。

预算按 **0.25 → 0.50 → 1.00 秒**，范围不自动扩大。
每个尝试的预算先运行固定旧 final 诊断：
- train origins：5040、5088、5136、5184、5568、6576。
- 每个 origin：确定性动作、采样 seed 0/1/2；同一环境种子，保持原预登记口径。
- 24 个独立进程回合＋24 个共享进程回合，共 48；各预算采用相同案例顺序。
- 只读策略；前后参数 hash 不变；逐步记录阶段、预算、实际耗时、降级、库存、服务和经济指标。
- 无可执行方案的回合立即停止并保留失败现场；不补采一条成功轨迹替代它。

对通过者继续：三个种子各自**新初始化、8 批**，串行；全部通过后再做一次
**4 小时共享进程**验收，保留原 train-only 前后独立进程对照。稳定性阶段明确
固定旧 final 诊断策略及不更新参数，不能用新增优化器训练替换原协议。
4h 以共享阶段单独计时，完整跑完当前回合；前后对照不计入 4h。
先验收前后服务/物理/终点、参数不变，并报告耗时和经济差异，不能因为求解有
降级就要求前后经济结果逐位相同。提前失败不算通过，不重复直到偶然成功。

选择首个完整通过“48回合＋3×8批＋4h”的预算后停止增加预算；三档都失败则停止。
这不是对所有可能预算的性能最优搜索，而是在已批准范围选最小合格预算。

质量门槛：
- 预登记任务完整，服务达到既定标准，物理无违规，满足既定统一终点目标。
- 不出现无合格执行方案；合格 A 降级允许，但单独列比例、成本、碳排和服务表现。
- 不可达/不合格轨迹如实保留并使对应资格失败，不放宽终点规则或删样本补满。
- 固定输入与执行规则；A/B 共享原预算，不补时、不给失败新增奖励修复。
- 所有选择只用 train；validation/test 封存。

## 5. 卡 D：训练放行与后续顺序

输出一份可审核放行报告：完整 SHA、配置/锁/输入摘要、选定预算、资格结果、
性能优化对照、512批耗时估计、A降级经济表现、剩余风险及产物验签。
新冻结发布绑定资格证据、执行/停止/保存规则和预登记训练矩阵。
未通过任一必要门槛，不生成 `formal_training_ready=true`。

根据新对话用户授权的执行范围停在报告或继续：
1. 新初始化 seed0、512 批、主机串行；旧 final 不用于恢复。
2. 实时保留批前状态、每16批历史 checkpoint、失败现场；异常立即停止，不跳批。
3. Mac 审核完整性、末段走势、A降级/业务/物理/终点，做最终策略 train-only 诊断。
4. 审核后才安排 seed1、2；三种子均串行。后续完整 validation/test 另行安排。
性能达标不等于学习有效；训练跑完也不等于论文降本/减排结论成立。

## 6. 远程执行、交付与停止规则

沿用 `scripts.idc_remote`，不另建调度系统。常用命令形态：

```sh
python3 -m scripts.idc_remote status <已有job-id>
python3 -m scripts.idc_remote submit --job <唯一新job-id> -- <已提交的真实入口及参数>
python3 -m scripts.idc_remote watch <job-id>
python3 -m scripts.idc_remote collect <job-id>
```

尖括号是占位符，不可直接运行。新版候选/资格入口尚未实现，先完成卡 A 并记录真实命令；
不能照抄旧 `make train` 试运行以绕过发布拒绝。

- 先核对进程和已有 job，防止重复提交；测试、计时、短训、soak、长训互不并发。
- Mac 可同步开发/审核，提交不会改变主机固定 SHA；执行版本变化需要新 job 和资格处理。
- 新文件必须在输入集合中可用；缺失则显式建立新资产集合，不改既有已封存集合。
- 所有 run 标准五类产物，绑定 full SHA、config、lock、data/scenario、种子、命令和失败。
- 回传日志、checkpoint、失败快照，经 receipt 验签才交付；保留历史失败。
- SSH 断开不是训练失败；Windows/WSL 重启后先查状态与 checkpoint，不能假定自动恢复。
- 主机离线、依赖失败或资格失败就保留证据报告；不把长任务转回 Mac。
